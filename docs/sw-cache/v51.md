# v51 — the JIRA ticket view, over the tab (bc-0i27.6)

`public/app.js` grows a full-screen view for a JIRA ticket and a fold for the cancelled
ones; `public/style.css` grows the rules that lay both out.

## Why this one is a bump rather than an additive skip

No new file joins the shell, so `test/swbump.mjs` calls it an advisory rather than a
failure — nothing calls a member a cached sibling lacks. The stylesheet is what decides
it, and it is the third case the header names: **a stylesheet that lays out a control the
cached page draws anyway.**

A phone holding v50's `style.css` beside v51's `app.js` opens a ticket into `.card.open`
— which it has — and then draws, inside it, eight classes it has no rules for at all:
`.jira-beads`, `.jira-kids`, `.jira-text`, `.jira-thread`, `.jira-facts`, `.jira-fold`
and the two `.card.open.jira-card` padding rules. The result is not the app as it was; it
is the ticket view with its side padding fighting the card's own, a description rendered
without `pre-wrap` (so every newline in a JIRA description collapses), the children as a
default bulleted list, and the cancelled-tickets fold as a bare UA button. All of it is
readable and none of it is right, which is exactly the state a version exists to prevent.

The other direction is harmless — v51's stylesheet under v50's `app.js` is unused rules —
but a cache key is one number for both files and the worse direction is the one that
counts.

## What is in it

- `public/app.js` — `jiraFullHtml` and its two halves (`jiraBeadsHtml`, `jiraReadHtml`),
  the `jira-open` / `jira-beadify` / `jira-cancelled-fold` acts, `ensureTicketDetail`,
  `cancelledTicketsHtml`, and a `jira:` branch on `byKey` so an open ticket survives the
  25-second poll.
- `public/style.css` — the view (`.card.open.jira-card` and the `.jira-*` blocks under
  it) and the fold.

Nothing else in `SHELL` moved: the route it fetches (`GET /api/jira/ticket`) is API
traffic, which is never cached.

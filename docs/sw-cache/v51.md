# v51 — four settings on a repo row, not one (bc-6i88)

`public/monitor.js` replaces its one hardcoded per-repo control with a loop over four,
and `public/style.css` gains the rule that keeps the four rows aligned.

## Why this one is a bump rather than an additive skip

Two shell files changed together, which is the advisory. What makes it a bump rather than
a judgement call is the payload underneath them:

- **`repoTri` stopped reading `r.autoEndorseOwn` and `r.autoEndorseInherited`, and now
  reads `r.own[key]` and `r.inherits[key]`.** The server changed shape in the same
  commit (`spaceDetail` in `lib/spaces.js`). That is not a mixed pair `lib/swbump.js` can
  see — the other half is server-side rather than in SHELL — and it is the same failure:
  a phone holding v50's `monitor.js` against a v51 daemon reads `undefined` for every
  field it draws the pressed button from, so all four controls would light Inherit
  whatever the config says, and a press would write the answer the button did not name.
  The guard in `repoTri` covers the other direction (a v51 page against a payload with no
  `own`, which draws nothing rather than lying); the cache version is what covers this
  one.
- **`style.css` carries `.space-repo-what`'s `flex`/`min-width`**, without which the four
  rows are four differently-indented button groups rather than a column.

## What is in it

- `public/monitor.js` — `REPO_SETTINGS`, the table of four, and `repoTri` as a loop over
  it. The press handler and `saveSpace` were already generic and did not move.
- `public/style.css` — `.space-repo-what` takes the slack so the buttons line up down the
  rows.

## The number

v50 was the newest note when this was written. If this arrives at a downmerge to find
v51 taken, renumber it rather than leaving a gap — `test/swcache.mjs` refuses one, and
the add/add conflict on this filename is the whole mechanism that catches two branches
writing the same `const CACHE`.

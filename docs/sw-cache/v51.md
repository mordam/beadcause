# v51 — a tree whose nesting is drawn entirely in CSS (bc-rfnr.9.2)

A P0 card now expands into its own descendants, and what a v50 stylesheet does to that is
not "the app as it was" — it is the same rows saying something different.

The tree arrives from the server flat: every descendant at any depth, pre-order, with a
`depth` on each row (bc-rfnr.9.1). Nothing in the markup nests. The *only* place a
grandchild is distinguished from a child is `.p0-row`'s `margin-left: calc(var(--d) *
13px)`, where `--d` is an inline custom property the renderer writes from that depth.
Against a v50 stylesheet there is no `.p0-row` rule at all, so every row draws flush
left and a sixteen-bead epic reads as sixteen siblings. That is a wrong picture rather
than an unstyled one: the reader cannot see that bc-rfnr.9.2 hangs off bc-rfnr.9, which
is the entire thing the expansion was added to show.

Three more controls in the same pair, each drawn by the new app.js and unknown to the old
stylesheet. `.p0-tap` is the summary itself, now a `<button>` wrapping the id, the counts,
the title and the hint — stripped back to text by the stylesheet, so without it the whole
top half of every P0 card renders as a native grey button with a border round it and its
own 13.3px system font. `.p0-acts` is the row holding the advocate button beside the new
`.p0-graph` link, which is where the graph went when the id pill stopped being an anchor;
unstyled it stacks and the link reads as a bare blue word under a button. `.p0-none` is
the sentence a P0 with nothing under it expands to, which is a caption at body size.

The fetch handler is network-first, so this pair only exists on an offline or flapping
load and heals on the next online one. It is bumped anyway for the reason v49 was: the
cheap half of the pair is a stale *stylesheet*, and a stylesheet that is missing is not
loud — nothing errors, nothing is blank, and the screen simply says a thing that is not
true about the tracker.

# v103 — Config is a pane of the shell now (bc-khoe.60)

`/config`, `/settings` and `/config.html` stop being an alias for the document
`public/config.html` and become a 302 to `/#config`, the way `/history` and `/releases`
already do. `SHELL` drops the three paths — `Cache.put` refuses a redirected response, so
leaving one in an all-or-nothing `caches.addAll` would reject the whole install — and
`VIEW_HOPS` gains them, so the worker can answer the same hop offline that
`lib/server.js` answers online.

**The failure an unbumped cache produces:** a phone already holding v102's `SHELL` has
`/config`, `/settings` and `/config.html` cached as documents. A tap on the Config pill —
now a `<button>` that shows the pane, no navigation involved — is unaffected either way.
What breaks is a stale link: a home-screen shortcut or an old notification pointing at
`/config` would hit the cache-first entry, get the document served instead of the 302,
and land on a page whose container this bead's own commit is what stops the shell from
ever building — `public/config.js` still runs there, so it is not a blank screen, but it
is a document nobody is going to update again rather than the pane that replaces it.

`public/config.html` is not deleted. It stays reachable offline exactly as it always was,
served network-first like any other page that is not in `SHELL` — this bump only changes
which of the two documents a same-origin request for these three names resolves to.

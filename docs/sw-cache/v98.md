# v98 — the last twelve view addresses stop being documents (bc-khoe.30.7)

The four views of this app became panes of one shell across bc-khoe.30: the ledger in v92,
Releases in v96, the advocate console in v97. Their **addresses** went on being documents
the whole time, because home screens hold them, notifications carry them and launchd opens
one of them. This is the branch that lands every one of them on its pane.

`lib/server.js` answers each with a **302 to `/#<view>`**:

| address | lands on | why it is on this list |
|---|---|---|
| `/history`, `/history.html` | `/#history` | the ledger, a pane since v92 |
| `/closed`, `/done` | `/#history?status=closed` | doors onto it, never pages (bc-nib3.7) |
| `/monitor`, `/advocates`, `/monitor.html` | `/#advocates` | the console, a pane since v97 |
| `/sessions`, `/work`, `/work.html` | `/#advocates` | the sessions view it absorbed |
| `/prs`, `/pulls`, `/prs.html` | `/#advocates?tab=prs` | the board, a **chip** of that view |
| `/releases`, `/deploys`, `/releases.html` | `/#releases` | Releases, a pane since v96 |

**A path the daemon answers with a 302 cannot be in `SHELL`.** `Cache.put` refuses a
redirected response and `install` is one all-or-nothing `addAll`, so a single one of them
left in the list would leave *nothing* cached on every installed phone for as long as that
worker lived. So all twelve come out, on top of the ledger's two. The `.js` behind each —
`history.js`, `monitor.js`, `montabs.js`, `prs.js`, `releases.js` — all stay, because the
panes are drawn with them.

**The board's three are the only hops in the app that name a chip as well as a view**, and
that is not decoration. `/prs` has always meant the *board*, not merely the page it is a
pane of, and `public/montabs.js` read that off `location.pathname`. After a hop there is no
pathname left to read. v97 built the slot for exactly this — `#advocates?tab=prs` — so the
fact crosses the `#` the way `/closed` carries `status=closed`. Without the `tab=`, `/prs`
would open the console on whichever chip was last used: plausible, wrong, and invisible
from outside, which is why `test/pagepaths.mjs` asserts the whole `location` rather than
the page at the end of it.

## Why this owes a bump, which is not the usual argument

The usual test is whether the change leaves a **broken** pair rather than a merely older
one, and by that test this change is safe in every direction. Stated against **v97**, which
is the shell a phone will actually be holding:

- **A v97 shell against this daemon.** Every path here is network-first, so the request
  goes out, the daemon answers 302, the fetch follows it to `/`, and the shell opens on the
  right pane. `fetchAndStore` refuses to store a redirected response, so nothing is
  poisoned. Correct, first try, on a phone that has not updated at all.
- **A v97 shell, offline.** `/monitor` hits the entry cached under that name — the old
  `monitor.html` document, whose scripts v97 already taught to run in either place. Older,
  not broken. Same for `/releases` against v96's document and `/history` against v92's.
- **This shell against an older daemon**, which is only the seconds of a deploy: the paths
  are served as the documents they still are, from the network, and the panes are never
  reached. Also the app as it was.

What makes the bump owed is the other thing `activate` does. It deletes every cache whose
key is not the current one — and nothing else ever removes a single entry. `install`
re-fetches everything in `SHELL` into whatever cache `CACHE` names, so a changed `sw.js`
under an unchanged version would add the new list *on top of* the old one, and the fourteen
entries this branch removed would sit there for the life of the app. The exact match at the
top of `fallback` would go on answering them with the old documents, `VIEW_HOPS` would never
be consulted, and the half of this change that is about being offline would never happen on
any phone that already has the app — which is every phone. The bump is what makes a
**removal** from `SHELL` mean anything at all.

That is worth stating separately because it does not follow from the mixed-pair rule at
all: the rule is about files that disagree, and this is about entries nobody wants that
nothing else can evict.

## What else moved in this worker

`VIEW_HOPS` and `viewAddress`, and one step added to `fallback` between the `ignoreSearch`
retry and the fall to `/`: a request whose path names a view is answered with
`Response.redirect` to that view's hash rather than with the index page. Without it, an
offline phone opening the `/work` shortcut misses the cache twice and is served the shell
**at `/work` with an empty hash** — Home, whatever was tapped, which is the acceptance
criterion of this change failing in the one place nobody looks.

It is deliberately *below* the two cache lookups, and that is what made it safe to write
before the panes had landed: a path still precached under its own name is answered by the
exact match long before this table is reached, so the rule only ever fires for a path that
has already left the shell — which is the same commit that makes it a redirect. That
self-gating is why the ledger could ship its half alone in v96-as-written, and it is what
`test/pagealias.mjs` now enforces in both directions: a pane that is live owes its paths as
hops, and a pane still `data-pending` must not have them.

`/closed` and `/done` gain something they never had: they are still not in `SHELL` and
still cannot be, but the answer to them is now knowable here, because the far end of the
hop is a fragment of a document this worker already holds rather than a page only the
daemon can name.

## The number

Written against v95 and claimed as **v96**, having been renumbered twice. `docs/sw-cache/`
is the scheme that makes that a loud failure rather than a silent one: two branches picking
the same `vNN.md` collide on the path, which git reports as an add/add conflict. Both of the
notes this branch met on the way in — v96 (bc-khoe.30.14, Releases) and v97 (bc-khoe.4, the
console) — reached `main` while this one was running its gate, and both kept their numbers
while this moved past them.

**And the silent half happened here too, exactly as v96's note predicted it would.**
`docs/sw-cache/v96.md` conflicted loudly. `public/sw.js:42` did not conflict *cleanly*
either way worth trusting — the `const` is one line that two branches both rewrite, and a
branch that read the absence of a conflict as an answer would have shipped a v98 note over
a v96 or v97 string. It was set by hand afterwards and re-read, which is the whole reason
that step is written down rather than assumed. `node test/swcache.mjs` checks it in about a
second.

Nothing in the pairs above depends on the number: they are about fourteen addresses leaving
`SHELL`, which is true against any shell that had them.

# v91 — a relay trail with no stylesheet under it (bc-bmry.4)

`public/app.js` gains two renderers on the epic card: `p0RelayHtml`, a status line on each
row of an epic's tree saying where a department relay has got to, and `p0RelayTrailHtml`,
the whole trail on the bead you open. Between them they draw seven classes that did not
exist at v90 — `.p0-relay`, `.p0-relay-sum`, `.p0-trail`, `.p0-trail-row`, `.p0-trail-who`,
`.p0-trail-when`, `.p0-trail-note`, `.p0-trail-flag` — and `public/style.css` gains the
rules for all of them in the same commit.

**A v90 stylesheet under a v91 `app.js` is the pair that forces the number, and both halves
of it are the same failure: unstyled text that still reads as a sentence.** The row's
`.p0-relay` is `flex: 1 1 100%` in a wrapping flex row, and without that rule it is an
inline span at body size sitting between a bead's id and its title — so `⇄ clio · check · 2
steps · 40m ago` is drawn *inside* the row's own text, at the same weight as the title,
sixty times down an epic's tree. Nothing errors and nothing is missing; the tree simply
becomes unreadable in the one place it is read fastest. The trail below is milder and the
same shape: `.p0-trail-note` and `.p0-trail-flag` are what put the sentence and the flag on
their own lines, and without them a step's note wraps into the column of the three marks
before it and reads as a caption on the timestamp rather than as what the role did.

The reverse pair — a v91 stylesheet under a v90 `app.js` — draws nothing at all, because no
v90 page ever emits any of these classes. That direction is merely older, which is the
direction this repo is happy to leave alone.

The server half forces nothing on its own. `/api/bead` gains `relay` and each tree row on
the epic card gains `relay`, and both are `null` for every bead no relay has ever run
on — which is every bead in every workspace but deluvia's studio. A page cached from a
newer deploy against an older daemon draws nothing for the missing field, which is the case
both renderers are written for and what `test/relayjournal.mjs` asserts first: a bead
nothing relayed draws the empty string, not an empty box.

## The number

Written against v80, claimed **v81**, and landing as **v91** — the collision the
[README](../../README.md) asks for, six times on the same note, and the quiet half fired
on four of the six.

bc-khoe.30.2 landed `v81.md` while this branch sat, so the first downmerge raised the
add/add on that path and that note kept the number; this one moved to `v82.md`. Then
bc-khoe.23 landed `v82.md` — the four Home pills — while the branch was *still* open, and
the same add/add came round a second time, on the number this note had just moved to; it
moved to `v83.md`. Then bc-khoe.30.3 landed `v83.md` — the panes shell — and took that
number too, with bc-ka5y.15.3, bc-r2b5.2 and bc-khoe.28 landing `v84.md`, `v85.md` and
`v86.md` behind it, so this note went to `v87.md`. And then bc-khoe.26 — the filter panel
coming apart into one pill per filter — landed `v87.md`, a fourth add/add on the number
this note had *again* just moved to, with bc-khoe.30.4's `v88.md` behind it, so it moved to
`v89.md`. And then bc-khoe.27.2 — ＋ on `My Epics` starting an epic — landed `v89.md`, a
fifth add/add on the number this note had just moved to, so it moved to `v90.md`. And then
bc-khoe.27.3 — ＋ on `All Beads` opening a create form — landed `v90.md`, a sixth add/add on
the number this note had just moved to yet again. The procedure is the same every
time and was followed every time: keep the note that landed, `git mv` this one to the next
free number, and move the version pairs in its own prose up with it. So *a v80 stylesheet
under a v81 `app.js`* became *a v81 under a v82*, then *a v82 under a v83*, then *a v86
under a v87*, then *a v88 under a v89*, then *a v89 under a v90*, and is now *a v90
stylesheet under a v91 `app.js`*. That pair is what the note is for, so it has to name the
shell a phone will actually be holding — which, now that v90 has landed, is v90.

**`const CACHE` in `public/sw.js` has now merged clean and silent on four of the six
downmerges, which is why it is opened by hand every time rather than only when git asks.**
On the first two it reported nothing because both sides had independently written the same
string — `beadcause-v81`, then `beadcause-v82` — so the line git kept was the line git
wanted and `sw.js` read as settled on its own. It spoke up only while `main` was running
several notes ahead of this branch rather than one, leaving `beadcause-v83` against
`beadcause-v86` and then `beadcause-v87` against `beadcause-v88` with nothing to agree on.
The fifth and sixth downmerges were silent again, both for the first reason: `main` was one
note ahead each time, both sides had independently written `beadcause-v89` and then
`beadcause-v90`, and this note's filename was the only thing that reported anything at all.
Set by hand to `beadcause-v91`. Six renumbers of one note, four of them silent in
`sw.js` and every one of them loud in the directory listing, is the whole argument for the
number living in a filename.

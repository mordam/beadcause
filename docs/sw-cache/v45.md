# v45 — three controls on the JIRA ticket row, which a v44 stylesheet lays out on top of the row itself (bc-0i27.7)

This is the v32 pairing rather than v44's, and it is the milder of the two kinds — but
it is the kind this repo has bumped for a dozen times, because what it produces still
reads as a working screen.

v44's rule is `.jira-card { display: flex; align-items: center }`: a row, with exactly
one child in it, the anchor that opens the ticket in JIRA. v45's `app.js` gives that card
a **second** child — the approve / discuss / cancel bar — and moves the rule to a column
so the two stack. A phone holding v45's `app.js` against v44's `style.css` therefore lays
the decision out *beside* the summary rather than under it, in the same flex row: on a
360px screen the ticket summary collapses to a few characters and three unstyled controls
take the rest of the width, with the destructive one no longer pushed to the far end,
because `.jira-acts .jira-cancel { margin-left: auto }` is in the file the phone has not
got.

Nothing throws and nothing is missing. The buttons work, the taps do what they say, and
the row is legible enough that you would not go looking for a stale cache — you would
think this was the design. That is the whole argument for the version: the failure is
cosmetic in a way that is indistinguishable from a decision somebody made.

The reverse pair — v44's `app.js` against v45's `style.css` — is harmless, as it always
is here: no element carries the new classes, so the new rules match nothing.

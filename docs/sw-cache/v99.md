# v99 — ＋ Add a bead-space, and the dialog behind it (bc-mc71w)

The space picker grew a last row. `public/spacebar.js` draws `＋ Add a bead-space` under
every group, and picking it opens `public/addspace.js` — a new file, and the first thing
in the app that can make a tracker exist rather than change one that already does.

**Two files that must not be mixed**, which is the whole of the argument:

- **new `spacebar.js`, cached `addspace.js` missing.** The row draws and the tap does
  nothing at all: `window.beadcause.addSpace` is undefined and the handler's optional call
  falls through in silence. A control that is drawn and inert is worse than one that was
  never offered — there is nothing on the screen to say why, and the obvious next move is
  to press it again.
- **cached `spacebar.js`, new `addspace.js`.** Harmless and invisible; the file is loaded
  and nothing ever calls `open()`.

Only the first is broken, and it is the one an unbumped cache produces on every phone that
already has the app: `SHELL` is served cache-first, so a shell holding v98 would go on
handing out the old `spacebar.js` — no row, no feature — while a phone that had *cleared*
its cache got both. That is not a mixed pair breaking, it is the change never arriving,
which is the second reason the header gives for bumping.

## What else is in the shell that was not

`/addspace.js`, and only that. The eight pages that carry the picker gained one
`<script src="/addspace.js">` beside the one they already had, and the tag is additive —
a cached page without it is the app as it was, which is exactly the state the bump is
there to end.

## The bar draws where it used to hide

`spacebar.js` hid itself below two workspaces: one repo and one space is nothing to pick
between. It is a choice now, because the last row adds a second — and the install that
had one tracker, or none, is precisely the one that needed the button. `scripts/topbar-check.mjs`
has a note about that rule; the picker still fits the first row either way, because the
add row is a row in the dropdown and not a control on the bar.

# v99 — repo views join the shell (bc-cft6f)

`public/viewhost.js` is new, and three files that were already in the shell gain members
it calls.

## Why this one is a bump rather than an additive skip

A new file that nothing else calls into is the shape that legitimately skips a bump — a
cached page without the `<script>` tag is the app exactly as it was, and a page *with* the
tag simply fetches it. That is not this change. `viewhost.js` is the caller and every one
of its three callees is a file a phone is already holding a cached copy of:

- **`hashroute.js` gained `route.add`**, which admits a repo's view to the grammar.
- **`panes.js` gained `panes.adopt`**, for a container built after the document was parsed
  — and its `known` check stopped being a `Set` snapshotted at load, because the grammar
  is no longer fixed by the time that file finishes running.
- **`viewbar.js` gained `views.add`**, which appends the pill.

A phone holding v98's three beside v99's `viewhost.js` gets `route.add` as `undefined`.
Every one of the three is reached through `?.` or a plain call that would throw, and the
`?.` half is the worse outcome: the host would run, find no grammar to extend, and add
nothing — an app that looks like a repo simply has no views rather than one that is
broken. That is the mixed pair `lib/swbump.js` calls a failure rather than an advisory,
and it is exactly the failure mode this file exists to prevent.

`style.css` carries it too, and independently: `.viewhost-head`, `.viewhost-age`,
`.viewhost-note`, `.viewhost-body` and `.beadlink`. A page cached without those draws a
repo's board with no chrome and with every bead id as the browser's default blue underline
on a dark ground.

## What is in it

- `public/viewhost.js` — new; asks `/api/views` which screens the repos declare, and gives
  each one an address, a pane, a pill and the SDK.
- `public/hashroute.js` — `route.add(view)` and `route.repoViews()`.
- `public/panes.js` — `panes.adopt(view, el)`, and `known` as a question rather than a
  snapshot.
- `public/viewbar.js` — `views.add(pill)`, appending at the end of the row.
- `public/style.css` — the pane chrome, and `.beadlink` for the bead ids a repo view draws.
- `public/index.html` — the `<script>` tag, last of them all: it adopts panes into the
  column and appends pills to the row, so everything it extends has to exist first.

## What is deliberately *not* in the precache

Anything a repo ships. Its script, its stylesheet and its payload all come from a checkout
only the daemon can read, and the worker installs its shell all-or-nothing: one repo whose
checkout has moved would make `caches.addAll` reject and take the whole offline shell down
with it. `test/repoviews.mjs` asserts that neither `/v/` nor `/api/views` is in `SHELL`.

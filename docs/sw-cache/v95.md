# v95 — Releases becomes a pane of the shell, and its container's two ids move (bc-khoe.30.14)

`/releases` stopped being the only way to reach the release board. Its container in
`public/index.html` was an empty `data-pending` box holding a place in the grammar since
v94; this fills it, so tapping the Releases pill from Home is a `display:none` swap rather
than a document load. The page itself is **untouched as an address** — `/releases`,
`/deploys` and `/releases.html` all still answer, because either of the first two can be
sitting on a phone's home screen.

**Two element ids moved, and that is what makes this a bump rather than a courtesy.**
`public/releases.js` runs in *both* documents and reaches for its elements by id, so the
page and the pane have to agree on what they are called:

| was | is | why |
|---|---|---|
| `id="releases"` | `id="rel-list"` | in one document `#releases` is the hash that names the view, so an element of that id is a **fragment target**: arriving at the pane scrolls it into view and throws away the scroll position `panes.js` has just restored |
| `id="observing"` | `id="rel-observing"` | `monitor.html` has an `id="observing"` too and folds into the same document under bc-khoe.4 — the bare name is a collision waiting on a sibling bead |

That is the mixed pair to reason about, and one half of it is genuinely broken rather than
merely older:

| the phone holds | against | what happens |
|---|---|---|
| v94 `releases.js` (looks for `#releases`) | v95 `releases.html` / `index.html` (only has `#rel-list`) | **broken** — `out` is `null`, the first `render()` throws, and `/releases` is a blank page under a working top bar. `report.js` files it as a P0, which is the loud half; the pane in the shell simply never builds |
| v95 `releases.js` (looks for `#rel-list`) | v94 `releases.html` | same shape, same result, from the other side |
| v94 `index.html` (pane still `data-pending`, no `releases.js` tag) | v95 anything | survivable and correct: `panes.has('releases')` is false, so the pill stays the plain `<a href="/releases">` it was and the page answers it. This is the app exactly as v94 shipped |

Both broken rows are the same pairing seen from either end, and both are cured by the
version moving as one — which is what a cache version is for. There is no migration to
write and nothing to feature-detect: a document either has the new ids or it has the old
script, never one of each, once this lands.

**Also in this bump, and smaller:** `public/stream.js` gained an exported `awake()` — is
*anything* on this page following the log — because the fallback deploy timer used to read
`following` off a handle this view held itself, and as a pane it holds none. A v94
`releases.js` against a v95 `stream.js` is fine (it never calls it); a v95 `releases.js`
against a v94 `stream.js` optional-chains to `undefined` and puts the thirty-second
fallback up, which is the safe direction — a poll too many rather than a strip that
quietly stopped refreshing. Neither combination is reachable after this version anyway.

# v82 — Releases is a view of its own, and the deploy strip left the PR board (bc-khoe.7)

The deploy strip — the box at the top of the PR board that says what is being built and
restarted *right now* — is gone from `public/prs.js` and is on a new page,
`/releases`, beside the two queues as cards. The pill row gained an eighth pill pointing at
it.

**This owes a bump for the ordinary reason and for one sharper one.** The ordinary reason
is a new page: `releases.html` is precached, and a phone holding a v81 shell has no entry
for `/releases`, `/deploys` or `/releases.js` at all — so the pill in its cached
`viewbar.js`… would not exist either, because `viewbar.js` is in the shell and the cached
copy has seven pills. That pairing is *merely older* and would have been survivable on its
own: seven pills and no Releases page is the app as it was.

The sharper one is `prs.js` and `style.css`, which are the mixed pair that is **broken**
rather than older:

| the phone holds | against | what happens |
|---|---|---|
| v81 `prs.js` (draws the strip) | v82 `style.css` | the strip's rules are still there — `.deploys`, `.deploy`, `.deploy-row` are all kept, because `releases.js` draws exactly the same markup — so this half is survivable and is why the version is not more urgent than it is |
| v82 `prs.js` (no strip, no `/api/deploys` poll) | v81 `monitor.html` | fine: nothing in that page's markup was the strip's |
| v81 `viewbar.js` (seven pills) | a v82 daemon | `/releases` answers, and there is no pill to reach it — the page is reachable only by typing the URL |
| v82 `releases.js` | v81 `prcard.js` | **this is the one.** `releases.js` destructures `esc`, `plural`, `ago` and `graphUrl` off `window.beadcause.prCard` at module scope, so a `prcard.js` older than that export set throws on load and the page is blank rather than degraded |

The last row is the reason this is a version and not a note: all four of those helpers have
been on `prCard` since bc-l8jp.6, so in practice the pairing cannot happen — but it is
exactly the shape (`a new script calling a function its cached sibling does not have yet`)
the rule at the top of `sw.js` names, and a cache key is how the app makes that shape
impossible rather than unlikely.

**Nothing was removed from the shell.** `/prs`, `/pulls`, `/prs.html` and `/prs.js` all
stay: the board is still a pane on the advocates page and still draws every row, every lamp
and the Ship button with its release count. What it no longer draws is what is being
deployed, which is now one pill away.

## The number

Written against v76 and claimed as v77, landing as **v82** — the collision the
[README](../../README.md) asks for, and it happened exactly the way it is described there.
Five notes reached `main` while this branch was parked (v77–v81), so the downmerge was an
add/add conflict on `docs/sw-cache/v77.md` alone: their note kept the number, this one moved
to the next free one, and the `const` in `public/sw.js` was set by hand to the highest note
in the directory. The `const` itself merged silently — both sides had written `v77` — which
is the failure the file's *name* being the number exists to catch. The pairs above are
restated against v81 because that is the shell a phone will actually be holding when this
lands.

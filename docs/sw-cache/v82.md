# v82 — `/panes.js` is new and precached, and it is what decides which view is on screen (bc-khoe.30.3)

`public/index.html` stops being Home and becomes the **shell**: one `[data-pane]`
container per view, all but one hidden, with `public/panes.js` swapping which one is shown
from the URL hash. The new file goes into `SHELL` and the version moves for it.

**Nothing here is a broken pair, and that is worth saying rather than assuming.** The three
ways a v81 phone can meet this branch all end somewhere sane:

* **v81 `index.html` beside v82 `viewbar.js`.** The cached document has no `<script
  src="/panes.js">` tag and no pane markup, so `window.beadcause.panes` is `undefined` —
  which is the *ordinary* answer on eleven of the twelve pages this row is drawn on. Every
  question the row asks it is asked with `?.` and defaults to no, so the row draws exactly
  the seven pills v81 drew, with the same hrefs. This is the deliberate asymmetry inside
  `viewbar.js`: `route` is reached flat because a page without the grammar is broken, and
  `panes` is reached with `?.` because a page without panes is Tuesday.
* **v82 `index.html` beside v81 `viewbar.js`.** The panes are in the markup and `panes.js`
  is loaded by its own tag in that same document, so the shell works; the old row draws
  History and Advocates as links, which is what this version draws them as anyway.
* **v82 `index.html` with no `/panes.js` in the cache.** The tag is a `<script src>` like
  any other and the fetch handler is network-first for anything outside `SHELL`, so it is
  either served from v82's cache or fetched. Without it, `.pane[hidden]` still hides the
  two empty containers — the attribute is in the markup, not applied by script — and Home
  is the only pane with anything in it, so the page is the page.

So the version is for the **precache**, not for a pair: a new file in `SHELL` that is not
in a cache is a file the app has to be online to have, and this one runs on boot on the one
page the app actually is.

**The stylesheet moved with it**, which is the pair `lib/swbump.js` would otherwise flag as
advisory: `.pane` and `.pane[hidden]` are new rules in `public/style.css` and the markup
that wears them is new in `index.html`. Both are inside the same precached set, so a phone
gets both or neither — and the failure if it somehow got the markup without the rules is
two empty divs stacked under Home rather than beside it, because the UA's own `[hidden]`
already hides them. Ugly for one load, not broken.

## The number

Written against **v81**, which was the highest note in `docs/sw-cache/` when this branch
was cut. If a downmerge finds `v82.md` already taken, this note moves up and `const CACHE`
is set by hand to match the directory — and it is opened and read *whichever way the merge
reported*, because [v81's own history](v81.md) is three downmerges of one branch where the
`const` conflicted loudly once and merged clean and silent twice, both times because the
two sides had independently written the same string. The number lives in a filename because
a filename cannot merge silently.

# v76 — a v75 page has no `/hashroute.js` tag, and both files that boot on it now call into it (bc-khoe.30.2)

`public/hashroute.js` is new and it is the only thing that knows what the URL hash means.
Two shell files stopped doing their own string work and started asking it, and both ask
**flat** — `window.beadcause.route.parse(...)` in `public/app.js`, `route.viewOfPath(...)`
in `public/viewbar.js` — with no `?.` and no `typeof` guard between them and the answer.
That is deliberate: a notification tap that silently opened nothing would be worse than
one that failed loudly, and the row saying nothing is current is a failure this epic has
already spent a browser check on.

**The pair is a page that predates the script tag.** The only way `hashroute.js` reaches a
document is a `<script src="/hashroute.js">` added to eight `.html` files on this branch,
and those eight files are precached. A phone holding v75's `index.html` beside v76's
`app.js` and `viewbar.js` has both callers and none of the callee: `window.beadcause.route`
is `undefined`, and the first thing that touches it throws a `TypeError` out of the IIFE it
is in. For `viewbar.js` that is the whole row — no pills, so no way off the page at all —
and for `app.js` it is `focusHash`, which runs from inside `load()`, so the inbox stops
drawing on the tap of a notification. Neither degrades; both stop.

It is the same shape as v75's `filterpills.js` one version earlier and the shape bc-nib3.3
went in for — a file added whole to `SHELL` whose only route onto the page is markup a
cached page has not got, called by another file in the same shell. The difference from v75
is which side of the red line it falls on: `filterPills.mount` is `?.`-guarded, so that one
is a control that quietly never appears, and this one is a `TypeError`. `lib/swbump.js`'s
fourth signal reports them differently for exactly that reason.

Everything else on this branch is additive or textual — the grammar module itself,
`test/hashgrammar.mjs`, and four files that read the view table from its new home. The
version is for the tag.

# v69 — one pill row replaces both bars, and every page becomes an app shell (bc-khoe.1)

`public/tabbar.js` is deleted and `public/viewbar.js` takes its place, at the *other end of
the screen*: the bar along the bottom is gone and a horizontally-scrolling row of view
pills sits under the top bar on all eight pages that used to load it. At the same time
every page stops being a document that scrolls and becomes a viewport-height flex column —
`html` and `body` clipped, the chrome as rows, and one element per page marked
`class="pagescroll"` carrying `overflow-y: auto`.

**Every mixed pair here is broken rather than merely older, and two of them leave a phone
with no way off the page it is on.**

*A v68 page under the v69 shell.* The cached HTML loads `/tabbar.js`, which no longer
exists — `addAll` would have refused it, so what a stale page actually gets is a 404 and no
navigation at all. It also has no `class="pagescroll"` anywhere on it, so under the v69
stylesheet the body is one viewport tall and clipped with nothing in it that scrolls: the
inbox is the first screenful and everything below it is unreachable. That is the worst pair
this cache has ever had, and it is two independent failures at once.

*A v69 page under the v68 stylesheet.* `.viewbar`, `.viewpill` and `.viewpill-icon` have no rules,
so the row draws as five unstyled links wrapped across two or three lines above the list —
readable, tappable, and about 90px of chrome. `.pagescroll` has none either, so the page
goes back to scrolling as a document, which still works; but `body` keeps the v68
`padding-bottom` reserved for a bottom bar that is not there, and `.compose-wrap` and
`.editmode` sit 54px higher than the screen they are pinned to. It looks like a page
mid-redesign.

*The `.has-tabbar` half.* `public/app.js` no longer sets `has-tabbar`, and the class is gone
from the stylesheet with the bar. A v68 stylesheet under v69 markup therefore reserves
nothing at the foot of a list that is still a document scroller, so the last card sits under
the ＋ button; a v69 stylesheet under v68 markup reserves the 54px the class asked for
inside a clipped shell, which is a dead band at the bottom of every page.

## What moved

- `public/viewbar.js` is new and in `SHELL` in `/tabbar.js`'s place.
- `public/style.css` gains the shell block (`html`, `body`, `.pagescroll`), the whole
  `.viewbar` / `.viewpill` block, and loses `--tabbar-h`, `.tabbar`, `.tab-item`, `.tab-icon`,
  `.tab-label`, `.tab-badge` and `.has-tabbar`.
- Fourteen HTML pages mark a `.pagescroll`; eight of them swap the script tag.
- `.mon-tabs` stops being `position: sticky` at `var(--topbar-h)` and becomes a row of the
  column, which is why `public/montabs.js` loses the `ResizeObserver` that published that
  variable. bc-ugd4 is what the offset was for, and the app shell is why there is nothing
  left to offset.

## The number

**v69 is this note's third number, and the collisions are the loud kind the
[README](README.md) asks for.** It was written as v67 against a `main` whose highest note
was v66 ([v66](v66.md), bc-rfnr.9.4). While this branch sat parked behind bc-y4is — the
read-only `gh` account, which stopped every delivery on this Mac for several hours — v67
went to bc-khoe.5 (the one-row top bar) and v68 to bc-1kwl.14 (the warm store's move to
localStorage), both of which reached `main` ahead of it. git reported v67 as an add/add
conflict on one path, which is exactly what that file naming exists to make happen: the
`const` in `public/sw.js` did **not** conflict on the first collision, because both sides
had written the same string to it.

The downmerge takes the next free number rather than the one the branch was written
against — a second document under a number `main` has already spent would make the cache
history ambiguous about which shell a given version names, and being unambiguous is the
number's only job.

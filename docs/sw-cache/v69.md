# v69 — the epic board becomes a grid and a card opens full-tab, and neither half works with the other one cached (bc-grut)

The "Epics assigned to you" board was a single vertical stack of full-width cards, and a
tapped card expanded its tree *inline*, between the board and the inbox list. bc-grut
makes the cards a responsive grid — one across on a phone, two, then three — and turns
the expansion into `p0FullHtml`, a fixed layer over the whole tab.

`public/app.js` draws nine class names that did not exist before: `.p0-cards` (the grid),
`.p0-full`, `.p0-full-top`, `.p0-full-head`, `.p0-full-body`, `.p0-full-acts`, `.p0-back`,
and `.p0-bar` / `.p0-bar-fill` (the progress reading on a collapsed card). Every one of
them is laid out entirely by `public/style.css`, which gains them on the same branch.

**The mixed pair is not "an old cache", it is a full-screen layer with no rules for it.**

A v68 `style.css` beside a v69 `app.js` is the expensive half, and it is the one that
looks like a working page rather than a broken one. `.p0-full` without its rule is a plain
`<div>` at the end of the board: not fixed, not the height of the screen, no scroller of
its own, no border under the head and no pinned acts row. So the tree comes back *inline*,
between the board and the list — which is precisely the shape bc-grut removes, and
precisely the shape bc-rfnr.9.9's scroll jump lives in — except that the page now also has
a "‹ Board" button in the middle of it, going back to a board that never went away. There
is nothing on screen to say the stylesheet is a version behind.

`.p0-cards` fails the same way and quieter: without `display: grid` it is a plain block, so
the cards stack one per line at every width and the phone is unchanged while the desktop is
back to a ribbon down an empty page.

The other direction is cheap. A v69 `style.css` beside a v68 `app.js` styles selectors that
nothing draws, and `.p0-acts` picks up `margin-top: auto` inside a card that is not a grid
item — a flex column whose content already fills it, so the auto margin resolves to nothing
and the row sits where it always did. The board is the board it was.

`node test/swbump.mjs` names all nine pairs on this branch as an advisory; this note is the
answer to it.

## The number

v69 because [v68](v68.md) is what `main` is on. Two other live worktrees —
`worktree-epic-any-priority-htoy` and `worktree-pill-row-khoe1` — had already written a
`v69.md` of their own when this was picked, which is the ordinary state of this repo rather
than a problem: whichever of the three lands first keeps the number, and the two behind it
take the next free one on their downmerge. That is what the one-file-per-version naming is
for — same number, same path, an add/add conflict git *must* report. The `const` in
`public/sw.js` will **not** conflict when that happens; all three sides set it to the same
string and git merges it in silence, so it has to be set by hand to match whichever note
survives, and `node test/swcache.mjs` is what catches it if it is not.

# v85 — the space's settings become a page, and a v84 shell has a chip over an empty pane (bc-khoe.10)

The selected space's settings left `monitor.html` altogether. They are `/config` now — a
new document (`public/config.html`, `public/config.js`), a new alias pair in `serveStatic`
(`/config` and `/settings`), and the eighth pill on `public/viewbar.js`'s row. The
**Config** chip and its `<section id="config">` are gone from `monitor.html`; `monitor.js`
loses `spaceHtml`, `tri`, `repoTri`, `loadSpace`, `saveSpace` and every `data-space-*`
press branch with them, and draws the roster alone.

**A v84 `monitor.html` under a v85 `monitor.js` is the direction that shows.** That page
still has the Config chip and the empty section behind it, and the new script knows nothing
about either: `public/montabs.js` reads the chips out of the HTML, so the chip still swaps
to a pane holding the "Reading this space…" placeholder it ships with, and nothing ever
fills it. The settings are still reachable — the pill row is drawn by `viewbar.js`, which
is in the shell and updates with it, so **Config** is on the row and `/config` serves. So
the failure is a dead chip beside a live pill, not a lost screen.

**The reverse — a v85 `monitor.html` under a v84 `monitor.js` — is the harmless one.** The
old script looks for `#config`, finds nothing (`const cfg` is null and every write through
it was already guarded), and falls back to drawing the settings card at the top of the
roster where it lived before bc-me2b. That is the app as it was two days ago: correct, and
one screenful of switches above the first advocate.

**The pill row and the new document have to arrive together, which is the real pair.** A
shell holding any `viewbar.js` before this one has no Config pill and no `/config`
precached, so a phone on that shell reaches the settings only through whichever
`monitor.html` it also has. Both files are in `SHELL`, so one `install` brings the row, the
page and its script at once — which is the whole reason the four new paths (`/config`,
`/settings`, `/config.html`, `/config.js`) are precached rather than left to network-first.

**`config.html` loads `/hashroute.js` before `/viewbar.js`**, which is a v81 requirement
this page was written before: since bc-khoe.30.2 the row asks `route.viewOfPath` on boot
and a page that omits the tag throws before it draws. `/hashroute.js` and `/panes.js` are
already in `SHELL` from v81 and v83, so the tag costs nothing new to precache.

`lib/presence.js` needs no change: `config` has been one of its `VIEWS` since bc-me2b gave
the chip a `data-view`, and `public/mirror.js` already names it. What changed is only who
reports it — `montabs.js` did, and `config.js` does.

## The number

exists to raise, and it raised it four times. bc-rfnr.9.5 was holding `v77.md` and
bc-khoe.27.1 `v78.md` when this note was written; both reached `main` first, and so did
bc-bmry.5 (`v79.md`), bc-8t3b (`v80.md`), bc-khoe.30.2 (`v81.md`), bc-khoe.23 (`v82.md`) and

collision: bc-henk's merge advocate was holding it unpushed on
`worktree-advocate-cards-henk` and said so, which is the one form of this clash the
filename cannot report — two branches writing the identical `const` line merge in silence.
Each of the others was an add/add conflict on the number this note was
holding: the note that landed first kept it, this one moved past all of them, and the
`const` in `public/sw.js` was set by hand to the highest note in this directory. The `const`
conflicted here only because the two sides had already diverged by whole numbers; had they
not, it would have merged in silence, which is why the number lives in a file whose *name*
is the number.

The pairs above are stated against **v84** rather than v76, because v84 is the shell a phone
will actually be holding. Nothing in the argument changes with the renumber: of the six
notes this one moved past, only bc-khoe.30.2 (v81) and bc-khoe.30.3 (v83) went near
`viewbar.js` at all, and none of them touched `monitor.html`'s Config chip or `monitor.js`'s

pane per view, and (v84, bc-henk) rebuilt the advocate cards below the card this note is
about. So a v84 shell holds exactly the chip, the script and the eight-less-one pill row this

`monitor.html`, but only to drop its `<h1>`, which bc-khoe.10 puts back reading
**Advocates** — so a v84 page under a v85 script also differs by a heading, and that
difference is a word, not a failure.

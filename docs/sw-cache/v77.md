# v77 — an expanded bead draws what happened to it (bc-rfnr.9.5)

A bead opened inside a P0's tree grew a last block: the pull requests that name it, and
its session — live by pid while a window is on it, archived by bead once one has
finished. It is drawn by `p0HappenedHtml` in `public/app.js`, styled by six new rules in
`public/style.css`, and it is a **pure addition to a screen that already exists**.

**The pair that breaks is a v76 `style.css` under a v77 `app.js`, and what it breaks is
which of these rows you can tap.** The block draws three kinds of row into one
`.p0-hap-row` box — a `<button>` into the pull request card, an `<a>` out to a session or
to GitHub, and a `<div>` for the two states that are deliberately not controls ("still
looking", "no session archived"). They are the same box on purpose, so that a reader
cannot tell them apart by weight before they know which is which; the *only* thing that
separates a control from a statement is `div.p0-hap-row { cursor: default; opacity: 0.75 }`
and the border the box gets from `.p0-hap-row` itself. At v76 neither rule exists, so
the whole block renders as unstyled inline spans: three unboxed lines of text, one of
which is a native `<button>` with the browser's default chrome on it and two of which
are anchors that look like body copy. The acceptance criterion for this bead is that a
bead with nothing to show **offers nothing to tap**, and the honest way to read the
unstyled version is that it no longer says which of them is offering anything.

The reverse — a v77 `style.css` under a v76 `app.js` — is the mixture that is merely
older: six rules matching nothing, on a page that never draws the block. That direction
is the app as it was, and it is why this is a bump about layout rather than about a
call into a member the other half lacks.

Two things ride along and neither would have owed a version on its own:

- **`.p0-hap-title { flex: 1 1 100% }`** is what puts each row's title on its own line,
  the same trick `.p0-rel-row` one block above uses. Without it the title, the repo pill
  and the rung all sit on one baseline and wrap into each other, so on a phone a bead
  with three pull requests is nine fragments in a paragraph and you cannot tell which
  rung belongs to which number. That is a legibility failure that looks like a rendering
  bug rather than like a missing stylesheet.
- **The tree row payload gained `session`** (`lib/server.js`, off `advocateSession`), so
  a cached page one version behind simply never draws the live half. That needs no cache
  version at all — it is a field an older renderer does not read — and it is noted here
  only so the next reader of this file knows the live link is a *server* fact and the
  archive is a fetch.

`SHELL` is unchanged: nothing new is precached, because everything this block needs is
already in `app.js` and `style.css`, and the two pages it links out to — `/session` and
`/bead-session` — have been in the shell since bc-nib3.5.

## The number

Written against v75, claimed v76, and landing as **v77** — the collision the
[README](README.md) asks for, and it happened the way it is described there. bc-me2b was
holding `v76.md` when this note was written and reached `main` first, so the downmerge was
an add/add conflict on that one path: their note kept the number, this one moved up, and
the `const` in `public/sw.js` was set by hand to the highest note in the directory. The
`const` alone would have merged silently — both branches wrote it `v76` — which is why the
number lives in a file whose *name* is the number. The pair above is stated against v76
because that is the shell a phone will actually be holding.

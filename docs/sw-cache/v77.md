# v77 — three notification sounds arrive, and an older stylesheet draws the audition unstyled (bc-ka5y.15.3)

`res/raw` gains `land.wav`, `drop.wav` and `chime.wav` beside the existing `blip.wav`, all
three generated by `scripts/sounds.mjs` and pinned byte-for-byte by `test/sounds.mjs`. The
shell change is the screen they are auditioned on: a new `public/sounds.html` +
`public/sounds.js` at `/sounds`, and the `.sound-*` rules `public/style.css` gains for it.

**Only the stylesheet is in `SHELL`.** `/sounds`, `/sounds.js` and the three `.wav` files
are deliberately left out — see the block beside `/icon.svg` in `public/sw.js` for why. So
the pair that matters here is not the usual one.

**The pair: an older `style.css` under the new page.** The page itself is never cached, so
it always arrives from the daemon and is always current; what a phone can be holding is the
previous stylesheet, which has no `.sound-*` rules at all. The audition then draws as
unstyled blocks — the pads stack, the guess buttons are default-sized `<button>`s, and the
✓ / ✕ the reveal marks answers with are gone with the rules that carry them in `::after`.

That last clause is the only part worth a number. Everything else degrades to
plain-but-usable: every control is still a real button, still labelled in words, still in
the right order. But the reveal's verdict is carried by `.is-right` / `.is-wrong`, and
without the stylesheet a wrong answer and a right one look identical. On a screen whose
entire purpose is telling you whether you named three sounds correctly, that is a page
quietly lying about the one thing it is for.

**The reverse — a new `style.css` on a phone that never opens `/sounds` — is nothing.** The
rules are namespaced `.sound-*` and no other page draws those classes.

## The number

Written against v76 and claimed as **v77**, and it was briefly claimed as v78 instead —
which is worth the paragraph, because it is the wrong move and it looks like the careful
one. Another worktree was already holding an unmerged `v77.md`, so skipping past it reads
as politeness. It is not: `test/swcache.mjs` requires the notes to be **contiguous**, and a
`v78.md` beside a `v76.md` with nothing between them fails the repo with *no note for v77 —
a renumber that skipped, most likely*. The numbers are a property of `main`, not of the set
of worktrees on this Mac, and only `main` can say which of two branches got there first.

So the rule is the one the [README](../../README.md) already gives, and it resolves at the
downmerge rather than before it: take the next number after the highest note **on main**,
and when two branches land holding the same one, the second to arrive gets an add/add
conflict on that path, keeps its own note under the higher number, and sets the `const` in
`public/sw.js` by hand to the highest note in this directory. The `const` alone would merge
silently — both branches write it the same — which is the whole reason the number lives in
a file whose *name* is the number.

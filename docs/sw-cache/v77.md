# v77 — an EpicAdvocate becomes a card, and a v76 stylesheet has no rule for its head (bc-henk)

Every advocate on `/monitor` is now a top-level card. `public/monitor.js` stops folding
each EpicAdvocate into a collapsed section of the repo advocate's card (`epicSections`) and
emits an `<article class="… epic-card">` per assigned epic instead (`epicCard`), directly
after the repo card it belongs to. `public/style.css` gains the rules that make that card
work: `.mon-card.epic-card`, and — this is the pair — `.epic-sum`, the button that is
both the card's title and its fold.

**The pair that matters is a v76 `style.css` under a v77 `monitor.js`.** `.epic-sum` is
`.mon-sum` plus an override, and `.mon-sum` is the 12px uppercase strip a *section* header
uses. Without `.epic-sum`, every epic card's name is drawn as a full-width uppercase
section heading, un-clipped, wrapping to two or three lines; the id pill beside it is a
flex item nothing has told to stop shrinking; `.adv-btn` and `.work-graph` in that head go
back to 32px and 36px, so Pause and *Open the epic* are visibly two kinds of control; and
`.mon-card.epic-card` itself has no padding override and no left rule, so the run of cards
loses the one thing tying it to the repo above. Nothing throws. Every press still works.
It is a page that looks like a page, laid out as though somebody had meant it — which is
precisely the failure this number exists for. Measured in Chrome at 393x852: the card is
107px with these rules, which is the difference between a repo with a dozen assigned epics
being 1656px and being a wall.

**The reverse — a v77 `style.css` under a v76 `monitor.js` — is inert.** The old script
draws epic *sections*; every rule above is scoped to `.epic-card` or `.epic-sum` and
matches nothing, so the page is the app exactly as it was.

`public/monitor.html` is untouched: the cards are written into the same `#mon` the roster
has always been written into, so there is no markup half to this at all.

## The number

**v77 was already claimed by another branch when this was written**, and it was taken
anyway. `bc-khoe.10` on `worktree-space-view-khoe10` held a `v77.md` of its own — the
claim register named it at the first write — and the obvious dodge was to take v78 and
leave the number to them. That is wrong here, and test/swcache.mjs is the reason: it fails
the repo for a **gap** in this directory, so a v76 followed by a v78 is a red main until
whichever branch owns v77 lands. A skip is not a cheaper conflict, it is the same conflict
moved onto somebody who has not agreed to it.

So this is the ordinary add/add, exactly as [v76](v76.md) describes it happening: whichever
branch reaches `main` first keeps the number, the second moves its note up, and the `const`
in `public/sw.js` is set **by hand** to the highest note in this directory. The `const`
alone would merge silently — both branches write it `v77` — which is the whole reason the
number lives in a file whose *name* is the number. The pair above is stated against v76
because that is the shell a phone will actually be holding either way.

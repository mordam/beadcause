# v77 — the four Home pills carry a count (bc-khoe.23)

`public/viewbar.js` gains a `counts(map)` beside `mark(id)` on `window.beadcause.views`,
and draws a `.viewpill-count` badge inside My Epics, Questions, PRs and Chats — on Home
only. `public/inboxfilter.js` gains the call that fills it, from its own `paint`, off the
per-kind numbers `surveyKinds` in `public/app.js` already hands it. `public/style.css`
gains the rule that draws the badge.

**The pair that is actually broken is a stale viewbar under a fresh filter's *absence*,
and it shows a number that is wrong rather than a number that is missing.**

*A v76 `viewbar.js` under a v77 `inboxfilter.js`.* The filter calls
`window.beadcause?.views?.counts?.(state.counts)` into a row that has no `counts`, which
is optional chaining and therefore silence: no badge is drawn, no error is thrown, and the
row is exactly the row v76 shipped. This half is harmless, and it is harmless on purpose —
every caller of that API takes the same fallback, because the row is on twelve pages and
the filter on one.

*A v77 `viewbar.js` under a v76 `inboxfilter.js`.* This is the one worth a version. The row
draws all four badges at their initial `0`, because zero is what a badge says before the
first poll lands — and the poll never lands, since nothing on the page has a `counts()` to
call. So Home shows **My Epics 0 · Questions 0 · PRs 0 · Chats 0** over a list with forty
cards in it. A badge that is missing is a feature that has not arrived; a badge that says
`0` over a full screen is the app lying about its own contents, and it is indistinguishable
from an empty tracker to anybody who has not read this file.

*A v77 `viewbar.js` under a v76 stylesheet.* `.viewpill-count` has no rule, so the number
draws at the pill's own size and weight, immediately after the label and with no tabular
figures — `Questions 4` rather than `Questions **4**`. Readable, tappable, correct, and
about four pixels wider per pill; the row still scrolls sideways because that is a
`.viewbar` rule and it is unchanged. Cosmetic only.

*A v76 page under any of it.* No markup changed on any page — the row builds itself from
its own list the moment it runs — so a cached document is not part of any pair here.

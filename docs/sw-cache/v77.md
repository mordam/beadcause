# v77 — ＋ becomes a function of the kind, and a v76 stylesheet draws it anyway (bc-khoe.27.1)

Home's ＋ was a fixed part of the chrome: one button, drawn at load on all five kind
screens. It belongs to the view now — `My Epics`, `Chats` and `All Beads` have a create,
`Questions` and `PRs` are queues of things waiting on a word from you and have none.
`public/inboxfilter.js` gains a `compose` flag per kind and a `composes()` that answers it
for the lit pill; `public/app.js` gains `paintCompose`, which hides `.compose-wrap`,
toggles `body.has-compose` and shuts the repo picker on every change of kind;
`public/style.css` gains the one rule that makes `hidden` mean anything on a flexed
wrapper; `public/index.html`'s comment above the button says so.

**The pair that must not be mixed is `app.js` and `style.css`, and it is the stylesheet
case this file's header calls the one that actually bites.** A v77 `app.js` under a v76
stylesheet sets `hidden` on `.compose-wrap` and nothing happens: `display: flex` beats the
user-agent rule, so the button is still drawn on Questions and PRs — while
`body.has-compose` has been correctly *removed*, so nothing reserves the 76px it needs.
The result is ＋ sitting on top of the last card of a queue it cannot create anything in,
which is worse than either half of the change on its own.

**The two script directions are both merely older, and deliberately so.** A v76 `app.js`
beside a v77 `inboxfilter.js` never asks `composes()`, so ＋ is drawn on every kind exactly
as it was. A v77 `app.js` beside a v76 `inboxfilter.js` asks a filter that has no such
method, `?.()` gives `undefined`, and the `?? true` in `paintCompose` draws the button —
the same app as it was. That fallback is in the source for this reason and not only for
this one: losing the app's primary action to a file that did not load would be a worse
failure than drawing it one screen too wide.

`scripts/viewbar-check.mjs` stops measuring a zero-sized ＋, which is a browser check
rather than anything a phone holds.

## The number

Claimed as **v77** against a `main` at v76. If another branch reaches `main` with a
`v77.md` first, the downmerge is the add/add conflict this scheme exists to raise: keep
both notes, `git mv` this one up to the next free number, and set the `const` in
`public/sw.js` by hand to the highest note in this directory — the `const` itself merges
silently when two branches write the same string to it, which is exactly the failure the
filename prevents. The pair above is stated against v76 because that is the shell a phone
will actually be holding.

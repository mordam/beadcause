# v54 — the question card grows a control, and the stylesheet grows its rules (bc-jg0w)

`public/app.js` draws the 📮 pill and the panel behind it — the way to hand a question to
somebody else from the phone — and `public/style.css` gains the five rules that lay them
out.

## Why this one is a bump rather than an additive skip

It is the named mixed pair, and `test/swbump.mjs` says so by name: four classes
(`.address-panel`, `.address-say`, `.address-row`, `.address-typed`) are newly drawn by one
half of SHELL and newly styled by the other. A phone holding a cached v53 `style.css`
against a v54 `app.js` opens the panel and gets an unboxed run of unstyled buttons and a
bare text input sitting between the pills and the question — a control that still works,
laid out as though it were prose, which is exactly the "looks like a working page" failure
the version exists to prevent. The fetch handler is network-first, so the window is an
offline or flapping load; that narrows it and does not excuse it.

The pill itself is the milder half of the same thing: `.pill.for` is a `<button>` wearing a
class the cached stylesheet only knows as a `<span>`'s, so without the new rules it draws
with the user-agent button border and font inside a row of flat pills.

## What is in it

- `public/app.js` — `addresseeHtml` and `addressPanelHtml`, the `address` / `address-set`
  click handlers, `state.me` off the inbox payload, and the `address-input` keystroke path
  into `state.addressDraft`.
- `public/style.css` — `.pill.for` (and `.for.any`), `.address-panel`, `.address-say`,
  `.address-row`, `.address-btn`, `.address-typed`. Colour is deliberately not among them:
  the pill borrows `.pill.on` and `.pill.mine`, which this file already had.

## What is *not* a reason for it

The new route, `POST /api/bead/addressee`, is not. A cached page that has never heard of it
never calls it, and a page that calls it against a daemon too old to serve it gets a 404
and a toast — an addition on the server is not a mixed pair, and `lib/` is not in SHELL.

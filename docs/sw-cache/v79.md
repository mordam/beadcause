# v79 — a second axis on the card, and a v78 stylesheet that lays none of it out (bc-bmry.5)

Where a bead's *ruling* is — deluvia's `draft / in-review / approved / revise`, off the
labels `docs/APPROVAL_PIPELINE.md` defines — is now drawn beside where its branch is.
`lib/approvalcard.js` derives it on the daemon; `public/app.js` gains `approvalChipHtml`
in the card's meta row, `public/graph.js` gains `approvalRowHtml` on the bead sheet, and
`public/style.css` gains the twelve rules that draw both.

**The pair that must not be mixed is `graph.js` and `style.css`, and it is the stylesheet
case this directory's header calls the one that actually bites.** A v79 `graph.js` under a
v78 stylesheet emits `.approval-row` with seven spans inside it and the stylesheet has no
rule for any of them: no flex, no border, no background, no muted tone, no uppercase kind
label. What the sheet draws is a run of undivided text — `Approvalin-reviewA review packet
on the phone, waiting on a ruling.counts towards G2` — wedged between the adopt row and the
session row, both of which *are* boxed. Not a blank and not an error: a row that looks like
a rendering fault in the page around it. The chip in `app.js` fails the same way more
quietly, taking `.pill`'s uppercase and losing the `text-transform: none` that keeps
`in-review` spelled the way `bd list -l` spells it.

**It is not hypothetical on day one.** `dv-b5d.3`–`dv-b5d.7` already carry the bare `gate`
label, so there are beads in deluvia whose sheets draw this row the moment the daemon
restarts — before ward has labelled a single review packet.

**The other direction is merely older.** A v78 `app.js` or `graph.js` against a v79 daemon
never reads `q.approval` or `b.approval`, so the field arrives on the payload and nothing
draws it: the card and the sheet are the app exactly as it was. Both renderers also return
the empty string for an absent or empty field, which is the same case seen from the phone's
side and is asserted in `test/approvalcard.mjs`.

**Nothing in the payload forced this.** `toQuestion` and `/api/bead` each gained one field
that is `null` for every bead outside the pipeline — which is every bead in every workspace
but deluvia — so the shell would have been safe on the wire alone. The bump is bought by the
stylesheet, and only by the stylesheet.

## The number

Written and claimed against **v78**, which was the highest note in this directory when this
branch was cut. If it lands as something else, the reason is the routine collision this
scheme exists to raise — another branch holding `v79.md` reaching `main` first, an add/add
conflict on this one path, and the `const` in `public/sw.js` set by hand to the highest note
here. The argument above does not change under a renumber: what a phone would be holding is
some shell that predates this branch, and no shell before it has a single `.approval-*` rule
in its stylesheet.

# v53 — four settings on a repo row, not one (bc-6i88)

`public/monitor.js` replaces its one hardcoded per-repo control with a loop over four,
and `public/style.css` gains the rules that keep the four rows aligned.

## Why this one is a bump rather than an additive skip

Two shell files changed together, which is the advisory. What makes it a bump rather than
a judgement call is the payload underneath them:

- **`repoTri` stopped reading `r.autoEndorseOwn` and `r.autoEndorseInherited`, and now
  reads `r.own[key]` and `r.inherits[key]`.** The server changed shape in the same commit
  (`spaceDetail` in `lib/spaces.js`). That is not a mixed pair `lib/swbump.js` can see —
  the other half is server-side rather than in SHELL — and it is the same failure: a phone
  holding v52's `monitor.js` against a v53 daemon reads `undefined` for every field it
  draws the pressed button from, so all four controls would light Inherit whatever the
  config says, and a press would write the answer the button did not name. The guard in
  `repoTri` covers the other direction (a v53 page against a payload with no `own`, which
  draws nothing rather than lying); the cache version is what covers this one.
- **`style.css` carries `.space-repo-what`'s `flex`/`min-width` and `.space-repo-moot`**,
  without which the four rows are four differently-indented button groups rather than a
  column, and the note on the approval row draws at full weight as though it were a
  heading.

## What is in it

- `public/monitor.js` — `REPO_SETTINGS`, the table of four, and `repoTri` as a loop over
  it. The press handler and `saveSpace` were already generic and did not move.
- `public/style.css` — `.space-repo-what` takes the slack so the buttons line up down the
  rows; `.space-repo-moot` is the aside on the approval row while merges are yours.

## The number

This was written as v51, renumbered to v52, and is now v53 — it lost the race twice in
one ship, to bc-nib3.3 and then to bc-0i27.6. Both times the add/add conflict on
`docs/sw-cache/vNN.md` at downmerge is what said so, which is the mechanism sw.js's header
describes working exactly as intended, twice in an hour.

And both times, what did *not* say so was `const CACHE`: both branches wrote the identical
string to it, so that line merged clean and in silence — two versions' worth of shell
change under one cache key, with no conflict anywhere near it. Setting the number by hand
after taking the other branch's note is the whole of the fix, and the `vNN.md` filename is
the only thing in this repo that catches the need for it.

# v64 — a refused deploy draws the LaunchAgent as fields (bc-jrw0)

The deploy strip on `/prs` stops printing `rec.error` as a wrapped paragraph and draws the
verdict's keys: a bordered block with a row per fact — label, program, plist — and the
command that fixes it in `<code>` under a heading that says **Fix**. Two files in SHELL
move together for it: `public/prs.js`, which newly draws `.deploy-la`, `.la-head`,
`.la-fields`, `.la-row`, `.la-note` and `.la-why`, and `public/style.css`, which is where
all six of those get their layout.

**A v63 stylesheet under a v64 `prs.js` is the pair this note is about**, and it is the
quiet kind rather than the broken kind. Every word still renders: the block is a `<div>`, a
heading, six rows and a `<code>`, all of which inherit something readable. What is missing
is every rule that makes it a *block* — no border, no field grid, no monospace run for the
command, no dimming on the explanatory line. So a refused deploy draws as a paragraph-shaped
pile of labels in the middle of the strip, at the exact moment somebody is trying to read
one fact out of it quickly. The page works and looks broken, which is the failure the
version exists to prevent.

**A v63 `prs.js` under a v64 stylesheet is harmless.** The rules are additive; a strip that
never draws `.deploy-la` never matches them, and the deploy strip is the paragraph it always
was.

Nothing on the daemon side is cached at all — `lib/launchagent.js`, `lib/deploy.js`,
`lib/service.js` and `lib/notify.js` are the running build's, whatever the phone holds, and
the three-line ntfy push does not go through the shell in the first place. No new path is
added, which is why this is a bump for a mixed pair rather than for a file that would 404.

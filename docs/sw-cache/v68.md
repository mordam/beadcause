# v68 — the warm store moves from sessionStorage to localStorage, and a v67 page reads the wrong one (bc-1kwl.14)

`public/warm.js` keeps the payload each standing view boots from. Until v67 it kept it in
`sessionStorage`, which the browser wipes when the app closes — so a reopen had nothing to
paint and fell through to a cold `/api/questions`, one `bd human list` per workspace,
measured at 4.5s and about fifteen child processes. It keeps it in `localStorage` now, with
no TTL, a byte budget, and a shape version stamped on every entry. `public/app.js`,
`public/accountbar.js` and `public/console.js` move with it.

**The mixed pair is not "an old cache", it is two files disagreeing about where the cache
lives**, and it goes wrong in both directions at once.

A v67 `app.js` beside a v68 `warm.js` is the cheap half: every read is a miss, because
nothing ever wrote to the store the new file is looking at, so the phone is exactly as
fast as it was before the warm layer existed. Annoying rather than broken.

The expensive half is a v68 `app.js` beside a v67 `warm.js`. `warmBoot()` is wrapped now,
against exactly the payload skew a durable entry makes certain, and its `catch` calls
`warm.drop(...)` — which a v67 `warm.js` does have, so nothing throws. What it does not
have is any of the bound: a quota failure at v67 answers with `forget()` and empties the
whole store, which is the behaviour bc-1kwl.14 exists to remove, and the one the new
`app.js` is written as if were gone. It also does not have the `v` stamp, so every entry a
v68 build writes reads back at v67 as a payload of unknown vintage that nothing refuses.
The page still works. It simply behaves like neither version.

And `public/accountbar.js` gains a `warm.forget()` on the account switch, which is the
half that is a privacy rule rather than a performance one: the held payloads are narrowed
server-side by which account you are, they survive the app closing now, and switching
accounts is a `location.reload()`. A v67 `accountbar.js` beside a v68 `warm.js` reloads
into somebody else's inbox as its first frame — for the second or so before the fetch
behind it lands, which is precisely the frame the whole layer exists to draw.

## The number

v68 because [v67](v67.md) is what `main` is on — this branch was written against v66 and
took `v67` for itself, and bc-khoe.5's top-bar note landed there first. That is the loud
add/add on one path this directory exists to produce, and it is the ordinary state of a
laptop with several branches open rather than a problem: whichever lands second takes the
next free number, which is this one. The `const` in `public/sw.js` did *not* conflict —
both sides set it to `beadcause-v67` and git merged that silently — so it is set by hand
here to match the note.

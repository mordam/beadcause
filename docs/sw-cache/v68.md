# v68 — an epic roots work at any priority, and the wire renamed itself to say so (bc-htoy)

Only P0s could root work, take an `owner:` label, or be given an Epic Advocate. That was a
mistake: an epic *is* a decision — that is what filing one means — and priority says how
urgent the decision is, not whether it was made. `isRoot` in `lib/ownership.js` is now
`isP0(issue) || isEpic(issue)`, and the four decision points keyed off it (the dispatch
gate, the advocate gate, the inbox board, the owner stamp at filing) widened together.

**This is a wire rename, which is the only reason it needs a cache version at all.** No new
CSS name arrives with it — the priority pill each card now draws reuses `.pill`, `.pill.p0`
and `.pill.p1`, all of which exist at v67, so a v67 stylesheet under a v68 `app.js` is not
the failure here. The failure is a **v67 `app.js` talking to a v68 daemon**, and it is
silent in all three places it lands:

| v67 asks for | v68 sends | what a stale phone sees |
|---|---|---|
| `data.p0board` on `/api/questions` | `data.rootboard` | `state.rootboard` never updates, so **the whole epic board disappears** — no cards, no 🧭 buttons — and `underOwnedRoots` falls back to `owned: false`, which un-narrows the inbox to the flat list. Nothing says either happened |
| `board.p0s` inside it | `board.roots` | the same, one level down: `owned: true` with nothing to draw, which the client already treats as "a warming daemon", so it waits forever for a section that has already arrived under another name |
| `b.noP0` on `/api/bead` | `b.noRoot` | the **adopt row vanishes from the bead sheet** — the one hold in this app that never clears itself loses the only control that clears it |
| `GET /api/p0s` | `GET /api/roots` | 404 behind that row. `loadAdoptActions` swallows it by design (the sentence is the half that matters), so the picker is simply never built |

None of those four throws. A phone on v67 shows a plausible screen — an inbox with no
board, a bead sheet with no adopt control — which is exactly the shape a cache version
exists to prevent, and it is why the number moved even though the stylesheet did not.

The other direction is harmless: a v68 `app.js` against a v67 daemon reads `rootboard` off
a payload that has none, and the board's own `owned: false` default draws nothing rather
than drawing wrongly. That is the same first-seven-seconds state a restarting daemon
already produces.

**`.p0-*` class names did not move, deliberately.** `.p0-card`, `.p0-row`, `.p0-tree` and
the forty beside them are a namespace prefix rather than a claim about priority, and
restyling them would have made this a stylesheet version too — for nothing a reader can
see, and at the cost of pairing every rule in `public/style.css` against every renderer in
`public/app.js` across a deploy. The wire moved because a stale phone reads it; the class
names did not because only the stylesheet does, and both halves of that pair ship together.

# v83 — ＋ on All Beads opens a create form, and a v82 shell has nowhere to draw it (bc-khoe.27.3)

＋ became a function of the kind in v78: drawn on `My Epics`, `Chats` and `All Beads`,
absent on `Questions` and `PRs`. It did the same thing on all three of the ones that keep
it — start a chat session. This is the first of the two that makes it do the view's own
create: on `All Beads`, ＋ opens a form — title, type, priority, description, acceptance,
parent, labels, and the workspace it lands in — and filing it creates the bead through
`POST /api/bead/create`.

Four files move together. `public/inboxfilter.js`'s `compose` flag stops being a bare
`true` and names what ＋ creates (`chat` or `bead`), with a `creates()` beside `composes()`
that reads it off the lit pill. `public/index.html` gains the `#beadform` sheet.
`public/app.js` branches the ＋ click on `creates()` and gains the form's own state, its
three chip rows and its submit. `public/style.css` gains the handful of rules the form has
that a detail drawer does not.

**The pair to watch is `app.js` and `index.html`, and the branch is guarded on it.** A v83
`app.js` under a v82 document finds no `#beadform` section, so `beadFormEl` is null and the
whole `if (beadFormEl && beadFormFormEl)` block never registers. Left to `creates()` alone,
＋ on `All Beads` would then be a button that does nothing at all — silently, which is worse
than the chat it replaced — so the click tests for the sheet as well as for the answer and
falls back to starting a chat. The other direction is harmless on its own: a v82 `app.js`
under a v83 document never asks `creates()`, never reaches the sheet, and starts a chat
exactly as it did, with an inert `hidden` section sitting in the markup.

**The stylesheet direction is the ordinary one and it is real.** A v83 `app.js` under a v82
`style.css` opens the sheet — `.sheet` has been in the stylesheet since /graph — but
`.beadform-say[hidden] { display: none }` is not there, so the form's own status line is
drawn empty and permanently; `#beadform-ws-field.one .chip` is not there either, so the
single-workspace case reads as a choice you could have made differently; and `.beadform`'s
88dvh is not there, so the form is a 72dvh drawer showing four of its eight fields. None is
fatal and all three are exactly the "a name with no rule behind it" case this scheme exists
for.

**`public/inboxfilter.js` is safe in both directions and deliberately so.** An older
`app.js` beside a newer table never calls `creates()`. A newer `app.js` beside an older
table gets `undefined` from `?.()`, which is not `'bead'`, so it falls through to the chat —
the same fallback `composes()` has, for the same reason: losing the app's primary action to
a file that did not load would be a worse failure than one screen offering the wrong create.

Nothing about `lib/server.js` is cached, so `POST /api/bead/create` is either there or it
is a 404 the form reports on itself.

## The number

Written and claimed against **v78**, the highest note here when this branch was cut, and
landing as **v83** — the collision this scheme exists to raise, four times over, across
two downmerges of the same branch. On the first: bc-bmry.5 took [v79](v79.md), which was
the loud half — an add/add on this one path, which git must report — while bc-8t3b took
[v80](v80.md) and bc-khoe.30.2 took [v81](v81.md) without touching this file at all, so
those two were silent. On the second, after [#456](../../README.md) landed, bc-khoe.23 had
taken [v82](v82.md), and it was loud again for the same reason the first one was: both
sides had written `docs/sw-cache/v82.md`. Note what the `const` did on both passes — this
branch and `main` had independently written `public/sw.js` the *same* string, so that line
merged **clean, reporting nothing**. The filename is the only thing that raised any of it.
The `const` in `public/sw.js` is set by hand to `beadcause-v83`.

The pairs above are restated against **v82** rather than the v78 they were written against,
because v82 is the shell a phone will actually be holding when this deploys. The argument
survives the renumber unchanged: nothing in v79, v80, v81 or v82 puts a `#beadform` section
in `public/index.html`, a `.beadform` rule in `public/style.css` or a `creates()` in
`public/inboxfilter.js` — the three files this note's pairs are about — so a v82 shell has
exactly as little to draw the form with as a v78 one did. v82's own change is to
`public/viewbar.js` and to the badge rule beside it, and it neither draws nor suppresses
anything the form needs.

# v47 — approve, discuss and cancel on the JIRA ticket row, drawn by a stylesheet that has never heard of them (bc-0i27.7)

The v32 pairing again, and the third time this epic has produced it: a new control in
`app.js` against a `style.css` that has no rule for it.

v46's card is already a column — bc-0i27.5 made it one so the ingestion line could sit
under the row — so this is not the layout collapse v45 was. What v47 adds is
`.jira-acts`, the bar carrying Approve, Discuss and Cancel. Against a v46 stylesheet that
bar has **no rule at all**: no `flex`, so the three controls run as inline boxes with
whatever whitespace the template happens to leave between them; no `margin-left: 30px`,
so they start at the card's edge rather than lining up under the title the way the
ingestion line above them does; and no `margin-left: auto` on the cancel, which is the
one that matters — the destructive control loses its place at the far end and sits
directly beside Approve, exactly where a thumb aiming for Approve lands.

That last one is why this is worth a version rather than a shrug. Cancel arms before it
does anything, so a mis-tap costs nothing on its own — but a bar where the destructive
control has quietly moved next to the safe one is a layout that reads as deliberate, and
nobody looking at it would think to suspect a stale cache.

The reverse pair — v46's `app.js` against v47's `style.css` — is harmless, as always
here: no element carries the new class, so the new rules match nothing.

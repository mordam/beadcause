# v96 — Releases becomes a pane of the shell, and its container's two ids move (bc-khoe.30.14)

`/releases` stopped being the only way to reach the release board. Its container in
`public/index.html` was an empty `data-pending` box holding a place in the grammar since
v94; this fills it, so tapping the Releases pill from Home is a `display:none` swap rather
than a document load. The page itself is **untouched as an address** — `/releases`,
`/deploys` and `/releases.html` all still answer, because either of the first two can be
sitting on a phone's home screen.

**Two element ids moved, and that is what makes this a bump rather than a courtesy.**
`public/releases.js` runs in *both* documents and reaches for its elements by id, so the
page and the pane have to agree on what they are called:

| was | is | why |
|---|---|---|
| `id="releases"` | `id="rel-list"` | in one document `#releases` is the hash that names the view, so an element of that id is a **fragment target**: arriving at the pane scrolls it into view and throws away the scroll position `panes.js` has just restored |
| `id="observing"` | `id="rel-observing"` | `monitor.html` has an `id="observing"` too and folds into the same document under bc-khoe.4 — the bare name is a collision waiting on a sibling bead |

That is the mixed pair to reason about, and one half of it is genuinely broken rather than
merely older:

| the phone holds | against | what happens |
|---|---|---|
| v95 `releases.js` (looks for `#releases`) | v96 `releases.html` / `index.html` (only has `#rel-list`) | **broken** — `out` is `null`, the first `render()` throws, and `/releases` is a blank page under a working top bar. `report.js` files it as a P0, which is the loud half; the pane in the shell simply never builds |
| v96 `releases.js` (looks for `#rel-list`) | v95 `releases.html` | same shape, same result, from the other side |
| v95 `index.html` (pane still `data-pending`, no `releases.js` tag) | v96 anything | survivable and correct: `panes.has('releases')` is false, so the pill stays the plain `<a href="/releases">` it was and the page answers it. This is the app exactly as v95 shipped |

Both broken rows are the same pairing seen from either end, and both are cured by the
version moving as one — which is what a cache version is for. There is no migration to
write and nothing to feature-detect: a document either has the new ids or it has the old
script, never one of each, once this lands.

**Also in this bump, and smaller:** `public/stream.js` gained an exported `awake()` — is
*anything* on this page following the log — because the fallback deploy timer used to read
`following` off a handle this view held itself, and as a pane it holds none. A v95
`releases.js` against a v96 `stream.js` is fine (it never calls it); a v96 `releases.js`
against a v95 `stream.js` optional-chains to `undefined` and puts the thirty-second
fallback up, which is the safe direction — a poll too many rather than a strip that
quietly stopped refreshing. Neither combination is reachable after this version anyway.

## The number

Written and landed as **v96**, having been **v95** for about an hour. bc-khoe.10 (`v95.md`)
reached `main` while this branch was running its gate, so the downmerge was the add/add
conflict on the filename that this scheme exists to raise — the sixteenth of them. The note
that landed first kept the number and this one moved past it.

**The silent half happened here too, exactly as the v93 race predicted it would.**
`docs/sw-cache/v95.md` conflicted loudly, because the filename *is* the number. But
`public/sw.js:42` merged **without a murmur**, because both sides had independently written
the identical string `beadcause-v95` — a clean three-way merge of two lines that agree.
Nothing in the merge output mentioned it, and a branch that trusted the absence of a
conflict would have shipped a v96 note over a v95 `const`. The `const` was set by hand
afterwards and re-read, which is the whole reason that step is written down rather than
assumed.

The pairs above are stated against **v95** rather than v94, because v95 is the shell a phone
will actually be holding. The renumber is free at v95: bc-khoe.10 moved the space's settings
out of `monitor.html` into a new `/config` document and touched neither
`public/releases.js`, `public/releases.html` nor the Releases container in
`public/index.html`, which is checked rather than asserted — `git log 25a6e239..main --
public/releases.js public/releases.html` is empty. So every pair carries from v95 unchanged
and only the numbers moved.

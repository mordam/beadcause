# v102 — A deferral sets the card aside, and the toast has to know (bc-y9cof)

Answering a `defers: true` option used to leave the card in the inbox with all its
options on it. It sets the card aside now — the same `state.json` record `/api/dismiss`
writes — so the card leaves `/api/questions` and comes back when its gate clears or
somebody comments.

**One file in the shell changed: `/app.js`.** Nothing was added to `SHELL`.

**The mixed pair, and it is a lie rather than a breakage**, which is why it is easy to
miss:

- **new server, cached `app.js`.** The old toast reads `res.deferred` and prints
  *Deferred bc-x — still on your list* over a card the server has just hidden. The card
  is gone from the next poll, the sentence says it is not, and the two disagree on the
  one screen you would look at to check. Worse than a control that does nothing: the app
  states the opposite of what it did, and there is nothing to press to find out.
- **cached server, new `app.js`.** Harmless. `res.setAside` is undefined, which is
  falsey, so the toast takes the branch that says the answer landed and the card is still
  on the list — which is exactly true of an old server.

Only the first is wrong, and it is the one an unbumped cache produces on every phone that
already has the app: `/app.js` is served cache-first out of `SHELL`, so a shell holding
v101 would go on running the old toast against a server that had been redeployed
underneath it.

## The two new response fields

`POST /api/respond` gained `setAside` and `until` beside `deferred`. Both are additive
and both are read only by the toast, so an older client falls back to a sentence that is
true of what it can see.

They are two fields rather than one on purpose, and a client that collapses them is the
regression this note exists to name. `until: null` is the **ordinary** case — a bead with
no gate is set aside perfectly well and comes back on the next comment — so it cannot
also carry the meaning "this failed". `setAside: false` is that meaning, and it happens
when `bd` could not be read in the window between the answer going on the thread and the
record being written: the card is deliberately left visible, and the toast has to say so
rather than promise a return nothing measured.

## `mirror.js` is not in the shell

The Mirror's toast changed the same way and needs no bump for it — `/mirror.js` is not in
`SHELL` and is fetched normally. It is mentioned here only so the next reader does not go
looking for it in the list above and conclude something was missed.

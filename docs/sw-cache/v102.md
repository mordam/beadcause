# v102 — the space picker is one control, and a v101 stylesheet makes it disappear (bc-ka5y.34)

The picker was three boxes in one control: a `.spacepick-shown` span holding a label cut
to twelve characters, a `.spacepick-caret`, and the `<select>` laid over both of them at
`opacity: 0`. The span is gone. What you read is the select's own selected option now,
capped by a `max-width` and ellipsised past it, and the select is the box you see as well
as the one you tap.

Two shell files move together, and a phone caches them separately. `public/spacebar.js`
stops emitting `.spacepick-shown` and stops writing a second string into it — no
`shorten`, no `SHOWN_MAX`, no `shortLabel()` on `window.beadcause.space`. `public/style.css`
deletes `.spacepick-shown` and moves everything that was on it — border, radius, surface,
the 14px/1.2 longhands, the narrowed accent, the focus ring — onto `.spacepick select`,
which stops being `position: absolute; inset: 0; opacity: 0` and becomes an ordinary,
visible box with `max-width: 130px`, `overflow: hidden` and `text-overflow: ellipsis`.

**A v101 stylesheet beside a v102 script is the mixed cache that matters, and what it draws
is nothing at all.** The span the old rules style is not in the markup, so they match
nothing; the select is still `position: absolute; inset: 0; opacity: 0; border: 0` against
a `.spacepick` whose only remaining in-flow child has been taken out of flow — so the
control collapses to no width, invisible, and the absolutely-positioned select collapses
with it. The bar draws a mark and then empty space. The picker is not merely unstyled: it
is **gone and untappable**, on a screen whose lists are still narrowed to whatever the
filter says, with no control left to widen them and no text anywhere saying which repo you
are in. That is the app's one piece of context silently deleted, and a reload of the page
does not fix it — only a new shell does.

The reverse pair — a v102 stylesheet under a v101 script — is bad in the ordinary way rather
than the dangerous one. The span is still drawn and has no rules, so the cut-down label is
bare inline text with no surface; the select beside it is now a real visible box with a
border and a background, in flow rather than laid over anything, so the picker reads as the
same space twice, side by side, and the pair is wide enough to push the bar onto a second
row. Ugly, honest, and every control still does what it says.

## The number

Written against v98 and claimed as **v99**, landing as **v102** — the collision the
[README](README.md) asks the name to make loud, twice over. Three notes reached `main`
while this branch sat: v99 (bc-xl7n.76.2, the endorse row), v100 (bc-cft6f, repo views
joining the shell) and v101 (bc-mc71w, `＋ Add a bead-space`). Each surfaced as an add/add
conflict on the one path both sides wrote; the landed note kept its number every time and
this one moved past all three.

`const CACHE` conflicted **loudly** against v100, which is the lucky half rather than the
ordinary one — this branch held `beadcause-v99` where `main` had `beadcause-v100`, so the
line could not be missed. Against v101 it did **not**: this branch had already been moved
to `beadcause-v101` by hand, `main` arrived holding the same string for a different shell,
and the two merged clean with git reporting nothing at all. That is the exact failure the
paragraph above this one predicts, caught here only because the standing rule is to read
the `const` against **this directory** rather than against the merge — the doc conflicted,
the number beside it did not, and a matching string is not a matching shell. `node
test/swcache.mjs` checks it in about a second.

The pair above is stated against **v101**, because that is the shell a phone will actually
be holding. v101 is the first of the three that touches the picker at all: bc-mc71w adds
`＋ Add a bead-space` as a last row and `public/addspace.js` behind it, +58/−9 in
`public/spacebar.js`. It changes no `.spacepick` rule — its 38 new lines of
`public/style.css` are all `.addspace-*`, and v99 and v100 between them add 143 lines
naming `.spacepick` in not one of them. So a v101 stylesheet still carries exactly the old
`.spacepick` rules the argument above is about, and the disappearance it describes is the
same disappearance either way. What the added row changes is only what is inside the
control while it is gone: the shell that cannot be tapped is also the one holding the only
route to making a new bead-space.

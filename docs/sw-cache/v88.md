# v88 — `/panestage.js` is new and precached, and it is what builds the panes (bc-khoe.30.4)

v83 made `public/index.html` the shell: one `[data-pane]` container per view, all but one
hidden, with `public/panes.js` swapping which is shown from the URL hash. It deliberately
built nothing. `public/panestage.js` is the other half — the landed-on pane built first,
the rest after the first paint, and one `/api/poll` fanned out to all of them instead of
one park per pane. The new file goes into `SHELL` and the version moves for it.

**It is not a broken pair, and the three ways a v87 phone can meet this branch all end
somewhere sane:**

* **v87 `index.html` beside v88 `app.js`.** The cached document has no `<script
  src="/panestage.js">` tag, so `window.beadcause.stage` is `undefined`. The last line of
  `app.js` is `if (!window.beadcause?.stage?.register?.('epics', …)) buildHome()` — the
  optional chain answers `undefined`, and Home builds itself exactly as it did in v87. That
  fallback is the whole reason the boot was moved into a named function rather than into
  the stager.
* **v88 `index.html` beside v87 `app.js`.** The tag is there and the stager loads, but no
  pane ever registers, so the staged pass builds nothing and mounts nothing — while v87's
  `app.js` boots itself at load like always. The page is the page.
* **v88 `index.html` with no `/panestage.js` in the cache.** It is a `<script src>` like any
  other and the fetch handler is network-first outside `SHELL`, so it is served from v88's
  cache or fetched. Without it, again: `stage` is absent, `app.js` builds Home itself.

So the version is for the **precache**, not for a pair — a new file in `SHELL` that is not
in a cache is a file the app has to be online to have, and this one runs on boot on the one
page the app actually is.

**`public/stream.js` moved with it and is precached already.** Two additive changes: a
second argument on `listen`'s callback carrying the payload beside the events, and a
`standby: true` mount that runs only while no ordinary one is following. Both are new
surface rather than changed behaviour, so a v87 file beside a v88 caller loses the fan-out's
payload and the standby, and a v88 file beside v87 callers behaves identically to v87 —
`update.js` is the only existing listener and it takes one argument.

**No standby poll is actually mounted on this branch.** It goes up only when some built pane
declares a `wake`, and today Home is the one pane with contents and keeps its own poll. The
connection count is unchanged from v87; the machinery is there for bc-khoe.30.5 and .30.6.

## The number

Written against **v83**, the highest note in `docs/sw-cache/` when this branch was cut, and
**renumbered to v88 at the downmerge** — v84 through v87 landed on `main` while this branch
was open, so `v84.md` was already taken by bc-ka5y.15.3 and the file pairs named above moved
up with the note. `const CACHE` in `public/sw.js` was set to `beadcause-v88` by hand: the
number lives in a filename precisely because a filename cannot merge silently, and the
`const` is the half that would have merged without a murmur had the two sides been holding
the same number.

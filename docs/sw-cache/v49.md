# v49 — the three gestures, drawn by a stylesheet that has no rule for any of them (bc-p49x.2)

The v48 pairing again, one layer up. That version's stale half hid the *banner* saying
the screen was frozen; this one hides everything you can do while it is.

Edit mode now answers a tap, a hold and a hold-and-drag, and every one of them ends in
something drawn: an element lifted under your thumb (`.editpick`, `.editdrag`), a box at
the foot of the screen asking what you meant (`.editnote`), the list of what you have said
so far (`.editlist`), the count of it in the banner (`.editbar-count`), and the marks that
say which elements this pass has touched (`.editretype`, `.editretyped`, `.editsaid`).
Against a v48 stylesheet not one of those has a rule.

That is the broken half of the pair rather than merely the older one, and the note box is
why. It is `position: fixed` at the bottom of the viewport because that is where the
keyboard comes from and the whole point of it is to be typed into. Unstyled it is a plain
`<div>` appended to the end of `<body>` — below eight cards, below the fold, with no
background and no border. So the gesture appears to have done nothing at all: you hold a
card, the screen does not change, and the box that was asking you a question is a screen
and a half further down. The list and the count fail the same way, quieter — a pass you
cannot see is a pass you cannot review, and reviewing it before Save is the whole of what
the list is for.

`.editpick` and `.editdrag` cost more than they look, too. `.editdrag` is not decoration:
`pointer-events: none` is what lets a drop ask what is *under* the thumb instead of being
answered by the element already in it. On a v48 stylesheet a drop resolves against the
element being dragged, and every point lands "inside itself" — a recorded relationship
that is not wrong so much as meaningless, filed with a note that reads as if it were.

And one of them fails after the mode has ended, which is the worst place for it.
`.editmode[data-changes]::after` is the badge that says a pass is still held once the
banner has gone. Leaving edit mode puts every element back where the app has it, so
without that count the screen a person is left looking at is indistinguishable from a save
that silently lost their edits — the exact reading this whole design is arranged to
prevent. The attribute is set either way; on a v48 stylesheet nothing draws it.

The reverse pair is the ordinary additive one. A v49 stylesheet under v48's
`public/editmode.js` is the mode exactly as bc-p49x.1 shipped it: a freeze, a banner and
an anchor, with a handful of rules in the stylesheet that nothing on the page ever asks
for. Nothing in this version adds a file to the shell.

# v104 — the bead sheet says whether the hour fitted the window it was routed into (bc-nc6o.8)

`ran:<model>` records which model a finished session was billed to. It does not record
what the session cost, so nothing anywhere could answer the one question the routing epic
turns on: did this bead fit the window its tier picked? Sonnet-routed workers are hitting
the 200k wall, which means an unattended hour spent auto-compacting — the "botched
session" outcome `FALLBACK_MODEL` exists to avoid, arriving through the tiers somebody
*did* rate.

So a finished session now lands `ctx:fit`, `ctx:tight` or `ctx:over` on its bead, and the
sheet's model row draws the two verdicts worth acting on:

| half | what is new |
|---|---|
| `public/graph.js` | `modelRowHtml` draws `.model-ctx` and `.model-ctx.is-over` after the run |
| `public/style.css` | the two rules those names need, and nothing else |

**That pairing is the whole reason for this version.** A phone holding either cached half
alone still renders a page: the verdict arrives as unstyled inline text at the end of a
row whose other three spans are all deliberately weighted against each other — the model
at full strength, the tier muted, the run pushed right by a `margin-left: auto` that the
new span sits *behind*. Unstyled, "⚠ ran out of context" reads as full-strength body text
in the middle of that gradient, which is the "looks like a working page" failure the
version exists to prevent.

`fit` deliberately draws nothing, so the row's silence keeps meaning what it already
means. The label is written for all three outcomes — that is what makes "measured and
comfortable" distinguishable from "never measured", which is nearly the whole tracker —
but the row is read by somebody looking for what to fix, and "the routing did what it
promised" is not that.

The server half is additive on the wire: `pressures` is one new array on `b.model`
(`lib/modelcard.js`), and an older cached `graph.js` reading a payload that carries it
draws exactly what it drew before.

# v67 — the board is the inbox, and the two marks that say so have no rules at v66 (bc-rfnr.9.7)

The flat list under the board stopped being a second copy of it: with epics owned, the
beads under them are drawn once, in their epic's tree, and what is left underneath is the
things a tree cannot hold — chats, pull requests naming no bead, JIRA tickets, and a
question under nobody's P0 at all. Everything the inbox existed for goes with it, and that
is what this pair is about. `public/app.js` gains three marks: `.pill.p0-asks` on a
collapsed card and `.p0-kind-asks` on the section heading, both saying how many beads under
you are waiting on an answer, and `.p0-answer` inside an expanded bead, which is now the
only route on the phone to the box you answer a question in. `public/style.css` gains
`.p0-kind-asks`, `.p0-answer`, `.p0-card.asks` and a widened `.p0-head .pill`.

**A v66 stylesheet beside a v67 app.js is the pair that matters, and the answer control is
the half that hurts.** `.p0-answer` is a bare `<button>` at v66 — system font, grey face,
beveled on four sides, shrink-to-fit — sitting on the `.p0-bead-acts` row beside a graph
link that is a properly drawn 40px pill. It still works; it reads as a browser default that
escaped a stylesheet, which on the one control that answers a question is the worst place
on the page for that. `.p0-kind-asks` is worse in a quieter way: with no rule it inherits
the heading's own `text-transform: uppercase` and 0.08em tracking, so "1 asks you" is
printed as a tracked-out capitalised label beside the section name and reads as part of the
heading rather than as a count of what is waiting. `.p0-head .pill` at v66 is still
`.p0-head .pill.id`, so the new pill flexes and stretches across the gap to the counts,
which turns a card's head line into a bar.

`.p0-card.asks` is the one that would merely be missing: a leading edge 3px rather than
5px, which is a mark you do not notice rather than a mark drawn wrong.

Nothing throws and every tap works. That is the point — it looks like a rendering fault in
the section it is drawn in, which is exactly the failure this version number exists to
prevent.

## The number

v67 follows [v66](v66.md), which went to the bead expansion this builds on (bc-rfnr.9.4).
If `main` moves under this branch before it lands, the downmerge takes the next free number
rather than this one: a second document under a number `main` has already spent would make
the cache history ambiguous about which shell a given version names, and the number's only
job is to be unambiguous. The `const` in `public/sw.js` is not what to resolve a conflict
by — two branches routinely set it to the same string and git reports no conflict at all,
which is why the note is the file that has to carry the number.

The reverse pair — a v67 stylesheet under a v66 `app.js` — draws nothing at all, because no
v66 page emits any of these classes, and the list under the board is the list it has always
been. That direction is merely older, which is the direction this repo is happy to leave
alone.

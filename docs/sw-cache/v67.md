# v67 — the top bar is one row, and a v66 stylesheet draws the new one as rubble (bc-khoe.5)

The space picker had a full-width row of its own under a first row that was full at four
icon buttons. Now the buttons are rows in a menu behind the mark, the account chip is a
line inside that menu, and the picker sits beside the mark on a single row —
116px of sticky chrome with the tab bar, against 159px.

Three files move together, and two of them are shell files a phone caches separately.
`public/spacebar.js` stops drawing a bare `<select>` and draws
`.spacepick-shown` with the select laid over it invisibly; `public/accountbar.js` stops
drawing `.accountchip` and builds `.markmenu` / `.markmenu-gear` / `.markmenu-bare` and
an `.accountmenu-sub`, moving the mark's `<img>` inside a button and the whole thing into
`.brand`; `public/style.css` gains all six of those names, drops `.accountchip*`, and
re-points `.spacebar` from `flex: 1 0 100%` to `flex: 1 1 auto`.

**A v66 stylesheet beside a v67 pair of scripts is the mixed cache that matters**, and
what it draws is worse than an unstyled block — it is a top bar that looks broken in a way
that reads as the app having failed to load.

`.spacepick-shown` has no rules at v66, so the picker's label is bare inline text with no
surface, no border, no radius and no padding, and the caret drawn over it lands on top of
the first characters of the repo name. The `<select>` above it has no rules either, so it
is a *visible* platform select at its own default width sitting over that text rather than
an invisible layer — two controls stacked, one of them the operating system's own chrome,
which is the exact hole `appearance: none` exists to prevent. And `.spacebar` is still
`flex: 1 0 100%`, so all of it takes a second row anyway: the bar is two rows again with a
doubled picker on the lower one.

`.markmenu` has no rules at v66 either, so the trigger is a browser `<button>` — grey
face, beveled border, UA font — wrapped around the 26px mark, and `.markmenu-gear` is
`position: static` instead of a corner badge, so the ⚙ sits *beside* the artwork inside
that button and pushes the row wider. On the eleven pages with no mark the trigger is a
bare grey button with a gear in it, which is at least honest. `.accountmenu` still resolves
`right: 0` from a wrapper that is now at the left-hand end of the bar, so the menu opens
off the left edge of the phone with most of it unreachable.

Nothing throws, every control still works, and the app is still usable if you know what
you are looking at. That is the point: it looks like a rendering fault, and a person who
had just installed an update would read it as the update.

The reverse pair — a v67 stylesheet under v66 scripts — is the direction this repo is
happy to leave alone. The old `.accountchip` and `.spacepick select` rules are gone, so
the chip draws as unstyled text and the picker as a platform select on its own row; ugly,
but it is the previous release's layout with the paint stripped, not a control drawn twice.

## The number

v67 is the next free number after [v66](v66.md). If it collides with another branch
writing a `v67.md` of its own, git reports it as an add/add conflict on this path — which
is what the [README](README.md) asks the name to do, because the `const` in `public/sw.js`
would merge clean and silently at the same value. Keep both notes, `git mv` this one up,
and set the `const` by hand to the highest number here.

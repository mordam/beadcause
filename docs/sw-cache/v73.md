# v73 — the ten inbox kinds become six pills on the row

bc-khoe.2. `public/inboxfilter.js` and `public/viewbar.js` now talk to each other, and a
phone holding one from v72 and the other from v73 is a navigation that does nothing.

- **viewbar.js** draws six kind pills where it drew four page links, and five of them
  are `<button>`s that call `window.beadcause.inboxFilter.pick(id)`. Against a v72
  inboxfilter.js there is no `pick`, so every pill but History and Advocates is a button
  that swallows the tap silently — which is worse than a broken link, because a broken
  link at least fails visibly.
- **inboxfilter.js** pushes the lit pill out through `window.beadcause.views.mark(id)`.
  Against a v72 viewbar.js there is no `mark` and no `views` object at all (it was the
  array of pills), so the row draws `Home / Advocates / History / PRs` and lights
  whichever of them matches the path, over a list that a stored `beadcause.kinds`
  selection may have narrowed to one kind with nothing on screen saying so.

The pair is the whole reason for the bump. The rest travels with them and would not have
owed one on its own: `public/app.js` (two comments and the empty-state wording) and the
suites.

One thing that is *not* a cache hazard and is worth saying so: four of the ten kind ids
this app has written into `localStorage['beadcause.kinds']` were retired here —
`proposal`, `delivery`, `jira`, `endorsement`, and the three agent statuses became a
sub-filter. Every phone in the house has one of them stored. `set()` drops an id the
table does not know and has always done so, so the upgrade lands on an unnarrowed Home
rather than on an empty screen, and `test/inboxkinds.mjs` pins both halves of that.

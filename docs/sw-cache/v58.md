# v58 — the top-right buttons moved into a menu that a v57 stylesheet does not draw (bc-exqi)

Every page's top bar now ends in the signed-in address, and the loose icon buttons that
used to sit beside it — refresh, the endorsement queue, foundations, the gear, the way
out to Chrome — are rows inside the menu it opens. `public/accountbar.js` builds that
chip and that menu, and it builds them by **moving** the existing buttons into it: the
nodes are the same nodes, so a page script that wires `#refresh` by id afterwards still
wires the button the thumb lands on.

Which is exactly what makes the mixed pair broken rather than older. Against a v57
stylesheet there is no `.accountmenu` rule at all, so the menu is not `hidden` by a
`display: none` of its own — it is a plain `<div>` that has been handed four buttons,
sitting in normal flow inside a sticky bar, permanently open and stacked under the
brand. The refresh button has not gone missing so much as gone *somewhere else on the
page*, which reads as a broken header rather than an old one. And `.accountpick`, the
dialog behind **Switch accounts**, is a `<dialog>` with no width, no padding and no
backdrop: it opens as a hairline box in the middle of the screen.

The other half of the pair — cached v57 HTML with the new stylesheet — is the merely
older case and would not have earned a bump on its own: no `<script src="/accountbar.js">`
on the page means no chip, no menu, and the icon buttons exactly where they have always
been. It is the JS-new/CSS-old direction that fails, and the fetch handler being
network-first is why it only exists on a flapping load.

`/accountbar.js` joins SHELL for the reason `/spacebar.js` is in it, one degree stronger:
a page cached without it has no way to change which *life* the app is about — and,
because the menu is now where the page's own actions live, no refresh and no endorsement
queue either.

## What is not in this pair

The scoping itself is all server-side (`lib/accounts.js`, and the payloads in
`lib/server.js`), so a phone holding any generation of the shell sees the account it is
in. A cached page cannot show you the other account's beads by being old; it can only
fail to offer you the switcher.

## The number

This was written as v57 and lost the race to bc-0xil, whose note is now the one under that
name: the inbox's filter panel gained a bead search box on the same afternoon. `const
CACHE` merged clean and silent — both branches had written the identical string to it —
and the add/add conflict on `docs/sw-cache/v57.md` was the only thing that said a word.
Which is the filename doing exactly the job the header of public/sw.js gives it: two
changes under one cache key would have shipped a shell that never invalidated.

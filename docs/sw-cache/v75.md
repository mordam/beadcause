# v75 — the space's settings become a chip of their own, and a v74 page draws one with nothing behind it (bc-me2b)

The selected space's settings card left the top of the advocates roster and became the
**Config** pane on `monitor.html`'s own chip row — Advocates · PRs · **Config** · Mirror.
`public/monitor.html` gains the chip and a `<section id="config">` beside the board and the
Mirror; `public/monitor.js` writes `spaceHtml()` into that section instead of into `#mon`,
listens for presses on both panes, and fetches `/api/space` when the chip goes up.

**A v74 `monitor.html` beside a v75 `monitor.js` is the harmless direction, and it was
made harmless on purpose.** That page has no `#config`, so `monitor.js` finds nothing,
falls back to drawing the card where it has always been, and registers its press handlers
on `#mon` alone. What a person sees is the app exactly as it was.

**The reverse is the pair that matters: a v75 `monitor.html` under a v74 `monitor.js`.**
The old script knows nothing about a fourth chip, so the row draws a **Config** pill,
`public/montabs.js` swaps to it — that file reads the chips out of the HTML and needs no
change to find a fourth — and the pane it reveals holds the "Reading this space…"
placeholder the section ships with, forever. Nothing fills it, because filling it is the
line the old script does not have. Meanwhile the settings card is still at the top of the
Advocates pane, so the page has a chip that promises the settings and a roster that is
actually holding them. Nothing throws and every other tap works, which is the failure mode
this number exists for: a control that looks like a feature quietly not implemented rather
than a cache half-applied.

`lib/presence.js` gains `config` to its `VIEWS` set and `public/mirror.js` names it, which
is a server and a mirror concern rather than a shell one — an unknown view was already
shown as `other`, so neither is a pair.

## The number

Written against v74 and landing as **v75**, the next free number. Another branch was
holding this same path when it was written (bc-khoe.24), which is the collision the
[README](README.md) asks for rather than a mistake: whichever lands second `git mv`s its
note to the next free number and sets the `const` in `public/sw.js` by hand to the highest
note here, because the `const` is the one line two branches can write to the same value
and merge silently.

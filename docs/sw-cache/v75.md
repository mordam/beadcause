# v75 — My Epics is the board alone, and the fold that emptied it is gone (bc-khoe.28)

Home draws every view on top of the same page, and until this version it drew both halves
on all of them: the P0 board above and the card list below, whichever pill was lit. So no
pill showed only its own kind. `public/app.js` now asks `inboxFilter.current()` which pill
is lit and draws one of the two — the board on My Epics, the list on Questions, PRs, Chats
and All Beads — and the board's fold goes with the list it used to reveal, because on a
board-only view a fold is a control whose whole effect is to leave the screen blank.
`public/style.css` follows it: `.p0-kind` loses `min-height: var(--tap)`, `cursor: pointer`
and the button reset, because the heading is an `<h2>` now rather than a `<button>`.

**A v74 stylesheet under a v75 `app.js` is the pair that matters, and it is the heading.**
At v74 `.p0-kind` is written for a control: 44px of tappable height (`--tap`), a pointer
cursor, `-webkit-tap-highlight-color` and `border: 0; background: none` to undo the button
it was. Under the new `app.js` that rule lands on an `<h2>` that does nothing — so the one
line above the board is a thumb-sized target with a pointer over it and a tap highlight
when you press it, and pressing it has no effect at all. That is worse than the old fold
and worse than a plain heading: the phone says there is a control there, twice, and there
is not. Nothing throws, every card still opens, and the failure reads as a fold that has
broken rather than as a stylesheet from before the fold was removed.

The reverse pair — a v75 stylesheet under a v74 `app.js` — is the milder direction and is
still wrong: the fold button is still drawn and still works, but it loses its tap height
and its cursor, so the one line that a shut board leaves on screen becomes an 11px label
you have to know is pressable. Merely older is the direction this repo is happy to leave
alone; this one is a live control that stops looking like one, which is why the pair is
stated in both directions rather than only the first.

## The number

Written against v74, which is the shell `main` was on when this branch opened, and two
other live branches were holding 75 at the same moment — the claim guard named both. That
is the ordinary state of this file rather than a mistake: the number is taken as the next
free one on `main`, the add/add conflict is what makes the collision visible, and whoever
merges second renames with `git mv` and moves the heading with it. Renumbering in place is
what must not happen, because two documents under one number would end the one property the
number has. The note this builds on is [v74](v74.md) (bc-rfnr.9.7), which took the flat copy
of the board out of the list; this one takes the rest of the list off My Epics and the board
off every other pill.

# v90 — `index.html` grows the History pane, and loads `/history.js` to fill it (bc-khoe.30.5)

`public/index.html` had three panes and one of them had contents. It has two empty ones no
longer: the `data-pending` attribute came off `[data-pane="history"]`, the ledger's markup
moved in beside Home's, and the document gained a `<script src="/history.js">` tag to build
it. `public/history.js` itself is not a new file in the cache — it has been in `SHELL`
since the ledger became a tab, because `/history` is a page in its own right — so the
coupling that decides this number runs through that new script tag rather than through JS.

**The pair that needs the bump.** A v89 `index.html` in a phone's cache has no
`<script src="/history.js">` in it, so the container it does not have stays empty and the
History pill stays the `<a href="/history">` that v89's `panes.js` makes it: the app is v89
in full, which is fine. What is **not** fine is a v90 `index.html` beside a v89
`history.js`. The container's list is `id="hist-list"` now, where v89's file asks for
`id="history"` — the ledger would draw into nothing, with no error anywhere and a blank
pane where the record should be. That is a `<script src>` coupling, which is exactly the
shape `test/swbump.mjs` calls advisory-only (bc-nib3.10) because it cannot see it. This
note is the record that it was looked at rather than missed.

**Two other files moved and neither is a pair.**

* `public/hashroute.js` gained decision 5 — a view hash may carry a query,
  `#history?status=closed` — which is purely additive: `parse` answers `query: ''` for every
  hash that has none, and `hashFor(view)` called with no second argument behaves exactly as
  v89's did. A v89 caller beside a v90 grammar sees what it saw.
* `public/app.js`'s ⟳ handler asks `window.beadcause?.panes?.showing?.()` before reloading
  the inbox. Optional all the way down, and `undefined` on every page without panes — so a
  v89 `app.js` beside a v90 shell is v89's ⟳ (it reloads the inbox from whichever pane is
  up, which is the behaviour that was already there), and a v90 `app.js` beside a v89 shell
  is unchanged, because `showing()` answers `'epics'`.

**The one connection is now two mounts, and still one socket.** The History pane registers a
`wake` with `public/panestage.js`, which is what puts that file's standby poll up for the
first time — it was machinery waiting for this bead, and v88's own note says so. `standby:
true` means `public/stream.js` runs it *only* while no ordinary mount is following, and the
pane declares no `want`, so the union stays `presence`: the free park. The pane never
fetches on a wake; it sets a flag and re-reads once, quietly, the next time you look at it.

## The number

Written against **v88**, the highest note in `docs/sw-cache/` when this branch was cut, and
**renumbered to v90 at the downmerge** — bc-khoe.27.2 landed `v89.md` on `main` while this
branch was open, so the add/add collision this scheme exists to raise happened on that one
path, and the file pairs named above moved up with the note. `const CACHE` in `public/sw.js`
was set to `beadcause-v90` by hand: the number lives in a filename precisely because a
filename cannot merge silently, and the `const` is the half that did merge without a murmur
— both sides had written it the same string.

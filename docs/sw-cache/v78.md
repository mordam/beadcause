# v78 — the filter panel comes apart into one pill per filter (bc-khoe.26)

The collapsed filter line on Home and on /history is gone. Each group in it — the bead
search, PR status, bead status; status, priority, filed-by and the bead-id box on the
ledger — is its own pill in the row, opening its own chips. `public/filtermenu.js` is
rewritten around that, `public/inboxfilter.js` and `public/app.js` and `public/history.js`
stop answering for a summary line there is none of, and `public/style.css` draws the row.

**The pair that breaks is a v77 `inboxfilter.js` under a v78 `filtermenu.js`, and it
breaks with a `TypeError`.** The new `filtermenu.js` asks each group `narrowing()` to
decide whether to write the value on the pill, and that function is what a group whose
default *is* a narrowing answers `true` to with nothing chosen — it is how PR status keeps
saying `unmerged`. `inboxfilter.js` only gained it on this branch. A phone holding the
older half hands over sub-filter groups without one, and while the optional-call in
`narrowing()` means the read itself is safe, the two halves disagree about the whole shape
of the control underneath: the cached `inboxfilter.js` mounts with `narrowed`, which the
new `mount()` no longer takes, and the new `mount()` builds one `.filter-one` per group
where the cached `paint()` expects `ui.sel` to exist. `test/swbump.mjs` flags the pair by
name; this is not a judgement call.

**The stylesheet is the second half and it fails the other way round.** A v77
`style.css` under a v78 `filtermenu.js` has no `.filter-one`, no `.filter-note`, no
`.filter-summary.on` and — worse — still carries `#filters .filter-panel { left: auto;
right: 0 }`, which right-anchors every panel on Home. With the panels now hanging off the
pill *row* rather than off one menu at the end of it, that rule pushes an open panel back
under the scope switch and off the left of a 360px phone. It is a control you can open and
cannot read, which is the failure this bead is about arriving through the door marked
*fixed*. The reverse — a v78 `style.css` under a v77 `filtermenu.js` — is a handful of
rules matching nothing plus a summary line that has lost its bold state, which is merely
older; but the first direction is enough on its own.

`SHELL` is unchanged. Nothing new is precached: every file this touches
(`filtermenu.js`, `filterpills.js`, `inboxfilter.js`, `app.js`, `history.js`,
`style.css`) has been in the shell for many versions, and the bead adds no page.

## The number

Written against v77 and claiming **v78**. If another branch reaches `main` first this is
an add/add conflict on this one path and the fix is the one the [README](../../README.md)
describes: keep both notes, renumber this one to the next free file, and set `const CACHE`
in `public/sw.js` by hand to the highest note in the directory. The `const` alone would
merge silently, which is why the number lives in a file whose *name* is the number.

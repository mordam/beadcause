# v78 — ＋ becomes a function of the kind, and a v77 stylesheet draws it anyway (bc-khoe.27.1)

Home's ＋ was a fixed part of the chrome: one button, drawn at load on all five kind
screens. It belongs to the view now — `My Epics`, `Chats` and `All Beads` have a create,
`Questions` and `PRs` are queues of things waiting on a word from you and have none.
`public/inboxfilter.js` gains a `compose` flag per kind and a `composes()` that answers it
for the lit pill; `public/app.js` gains `paintCompose`, which hides `.compose-wrap`,
toggles `body.has-compose` and shuts the repo picker on every change of kind;
`public/style.css` gains the one rule that makes `hidden` mean anything on a flexed
wrapper; `public/index.html`'s comment above the button says so.

**The pair that must not be mixed is `app.js` and `style.css`, and it is the stylesheet
case this file's header calls the one that actually bites.** A v78 `app.js` under a v77
stylesheet sets `hidden` on `.compose-wrap` and nothing happens: `display: flex` beats the
user-agent rule, so the button is still drawn on Questions and PRs — while
`body.has-compose` has been correctly *removed*, so nothing reserves the 76px it needs.
The result is ＋ sitting on top of the last card of a queue it cannot create anything in,
which is worse than either half of the change on its own.

**The two script directions are both merely older, and deliberately so.** A v77 `app.js`
beside a v78 `inboxfilter.js` never asks `composes()`, so ＋ is drawn on every kind exactly
as it was. A v78 `app.js` beside a v77 `inboxfilter.js` asks a filter that has no such
method, `?.()` gives `undefined`, and the `?? true` in `paintCompose` draws the button —
the same app as it was. That fallback is in the source for this reason and not only for
this one: losing the app's primary action to a file that did not load would be a worse
failure than drawing it one screen too wide.

`scripts/viewbar-check.mjs` stops measuring a zero-sized ＋, which is a browser check
rather than anything a phone holds.

## The number

Written against v76, claimed **v77**, and landing as **v78** — the collision this scheme
exists to raise, and it happened exactly the way the paragraph this one replaces said it
would. bc-rfnr.9.5 was holding `v77.md` when this note was written and reached `main`
first, so the downmerge was an add/add conflict on that one path: their note kept the
number, this one moved up, and the `const` in `public/sw.js` was set by hand to the
highest note in this directory. The `const` itself merged silently — both branches wrote
it `beadcause-v77`, so git had nothing to report — which is the whole reason the number
lives in a file whose *name* is the number.

The pair above is stated against **v77** rather than v76, because v77 is the shell a
phone will actually be holding. Nothing in the argument changes with the renumber:
bc-rfnr.9.5 moved `app.js` and `style.css` too, but what it added is a block on the
expanded bead and six rules that draw it, and it neither asks `composes()` nor styles
`.compose-wrap`. A v77 stylesheet is therefore missing exactly the rule this note is
about — `.compose-wrap[hidden] { display: none }` — and the mixture it describes fails
the way it describes.
